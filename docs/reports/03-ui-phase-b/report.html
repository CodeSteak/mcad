1 Scope

Phase B adds editing in the 3D view to the browser UI. The code remains the single source of truth: handles change literals or write grid references, the parameter bar only changes the preview.

  • Handles of the line under the cursor, only for a literal or a variable with a literal; computed values are shown as a locked handle (gray ring). Kinds: cube/square corner, box/rect corner points, radius (sphere, circle, cylinder, torus), height (cylinder, linear_extrude), cylinder between two points, translate target (arrow old → new, handle at the target), rotation ring per axis (rotate), scaling at the bounding box corner, grid planes with a literal (handle on an edge of the grid box, drag along the axis), point variables, polygon/spline points, zone center via translate. Colors: literal orange, default value of a module parameter violet, pure reference turquoise, locked gray.
  • Dragging: DragStart → Drag (at most one message in flight, the last position wins) → Edits → the editor applies them as a live change and sends the source immediately; the engine tessellates coarsely, and finely after DragEnd. One drag is one undo step (live changes without history, at the end as one isolated event). Esc cancels.
  • Snapping in screen space (snap radius configurable, default 14 px) to grid points of the module and visible anchors (SnapTargets), target highlighted and labeled; the reference is written. 1D handles (height, radius, plane) snap to grid planes of the same axis and write g.name (new in cad-eval). Alt: no snapping, numbers rounded to the step size (settings, default 1 mm / 15°).
  • Parameter bar next to the view in module context: number (input field + slider), bool (switch), vector (three fields); reset per parameter, marking of changed values, "Reset all", values per module until the end of the session, "Apply as default" (SetDefault). Preview via SetContext { overrides }.
  • Inline controls for number and bool literals of assignments at the end of the line (slider, switch); one slider drag is one undo step.
  • Ctrl+click on a grid or anchor expression jumps to the declaration.

Changes to Rust crates: cad-eval (locked handles as locked_handles, SnapRef::Plane with a check that after writing, the handle lies exactly on the plane and the plane is visible at that location), cad-session (Drag always answers, SetDragOptions, scene with locked_handles), protocol types regenerated.

6 Known limitations and deviations

  • Jump to the grid declaration with Ctrl+click instead of a plain click: a plain click must still set the cursor, otherwise grid expressions would not be editable. The UI only knows the references of a module in module context (cursor in the module).
  • Without Alt, the handle snaps if a target is within the snap radius, otherwise numbers are written (rounded). A handle that consists only of references (e.g. box(g[…], g[…])) never turns into numbers without Alt; it only switches between targets.
  • Snapping of 1D handles only to planes on which the handle lands exactly after writing g.name (same origin and scale along the axis). Under a translated subtree or with center = true/d = (factor 2) there are therefore no plane targets; otherwise an expression such as g.deckel - 5 would be written, which locks the handle.
  • Point handles are dragged in the plane through the handle perpendicular to the view direction (2D points in their xy plane); nothing changes along the view direction. For a specific axis, a standard view helps.
  • Undo group: at the end of the drag the total change is undone once and re-applied as one history entry; this causes one additional re-evaluation from the cache.
  • Inline controls only appear for assignments with a number or bool literal (spec, value types); the range depends on the value at the start of the drag (0 … 2 × value, at least 10).
  • Parameters without a default value are set to 0 / false / [0, 0, 0] on reset (spec table); strings and lists are read-only.
  • The measurements come from headless Chromium with SwiftShader.
