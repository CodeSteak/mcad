6 Bekannte Grenzen und Abweichungen

  • Kanten einer Zone, geöffnete Flächen: die Ansicht prüft an den tessellierten Zonen-Meshes (Toleranz 1,5 × Sehnenfehler); die Engine wählt mit der exakten Kernel-Klassifikation. In Grenzfällen (Kante genau auf einer gekrümmten Zonenfläche) kann die Ansicht abweichen; im Test stimmen Anzahl und Engine überein.
  • sweep-Pfad: die Kurve wird in der UI nach demselben Verfahren wie in der SMLib-Fassade interpoliert (kubisch, Sehnenlängen, bei drei Punkten zwei Zusatzpunkte); ändert sich das Verfahren im Kernel, weicht die Anzeige ab. Der Startrahmen folgt sc_sweep (x = globales X in die Normalebene projiziert).
  • Profil von linear_extrude/rotate_extrude: gezeigt wird das Mesh der direkten Kinder (2D, flach in ihrer Ebene); z-Verschiebungen von 2D-Transformationen gehen dabei wie in der Engine verloren.
  • Zone über translate: der Cursor auf der Zone zeigt nur Zone und Kanten, nicht das Koordinatenkreuz der Transformation (Spec-Zeile „Cursor auf einer Zone“ geht vor); der Griff am Zonenmittelpunkt bleibt.
  • Neu einpassen: automatisch nur, solange die Kamera seit dem letzten Einpassen nicht gedreht/verschoben/gezoomt und kein Griff gezogen wurde; „Alles zeigen“ und die Standardansichten stellen diesen Zustand wieder her.
  • Achsgebunden: Achsen des lokalen Systems des Griffs (bei 2D-Punkten nur x/y); mit Umschalt wartet der Griff, bis 6 px Bewegung die Achse bestimmen. Wird die Achse erst während des Ziehens gewählt, geht die Achslinie durch die aktuelle Lage.
  • Offene Fläche neben Körpern auf oberster Ebene ist eine implizite Vereinigung und damit ein Fehler („zuerst thicken“) – Spec-konform, im Test getrennt geladen.
  • Einige Ergebnisse hängen am Kernel: dose_shell.scad ist wegen F1 derzeit rot (Zeile rot, Körper ohne shell); griffschale.scad verwendet deshalb $chamfer = 4 (auf beiden Plattformen ein korrekter Hohlkörper); die Tests C08, C17 und C18 prüfen zusätzlich, dass ein „ok“-Knoten Geometrie hat.

7 Gefundene Fehler in fremden Crates

Nicht behoben (andere Crates als dieser Auftrag); minimale Beispiele zum Nachstellen im Browser oder mit cad check datei.scad (cad-cli, nativer Kernel).

F1 shell eines verrundeten Körpers: leeres oder falsches Ergebnis ohne Fehler, sonst Fehler je nach Maßen, Zonen, Plattform und Verlauf

Crate: kernel-smlib / smlib (sc_shell), Meldung in cad-engine
grid g { z: o = 18; }
shell(1.6) { box([0, 0, 0], [90, 34, 18], $fillet = 5); zone(g.o, d = 1); } // ok, aber leer
shell(1.6) { box([0, 0, 0], [90, 34, 18], $fillet = 6); zone(g.o, d = 1); } // ok, Außenwand fehlt
shell(1.6) { box([0, 0, 0], [90, 34, 18], $fillet = 3); zone(g.o, d = 1); } // SM_ERR (1001)
// Maße von examples/spec/dose_shell.scad (dort mit grid g { z: o = 30; }):
shell(1.5) { box([0, 0, 0], [50, 35, 30], $fillet = 4); zone(g.o, d = 1); } // self-overlapping

Im Browser (Wasm): $fillet = 5 meldet „ok · 1 Fläche geöffnet“, das Ergebnis hat aber 0 Dreiecke und keine Bounds – die Ansicht zeigt nichts, ohne Fehler. $fillet = 6 meldet ok, die Bounds sind 1,6 … 88,4 statt 0 … 90: es fehlt die Außenwand, übrig ist nur die nach innen versetzte Fläche. $fillet = 3 scheitert mit „SmApiShellBrepFull failed: SM_ERR (1001)“, die Maße von dose_shell.scad mit „shell produced an invalid (self-overlapping) solid at 11 face(s)“ (auch nativ) – dose_shell.scad ist deshalb rot. Nativ (cad check) weichen die Ergebnisse ab ($fillet = 6 scheitert dort mit SM_ERR, leere Ergebnisse meldet cad check nicht). Außerdem hängt das Ergebnis von einer zusätzlichen Zone ab, die keine Fläche öffnet (translate([90, 17, 8]) cube([4, 10, 6], center = true)), und davon, was vorher in derselben Sitzung ausgewertet wurde. Zwei benachbarte geöffnete Flächen (zone(g.oben) und zone(g.vorn)) scheitern mit SM_ERR (1001). Scharfkantige und gefaste Körper ($chamfer) ergeben korrekte Hohlkörper. Vorschlag: Ergebnis prüfen (Volumen, Bounds) und ein leeres oder ungültiges Ergebnis als Fehler melden.

F2 surface(points) mit 2 × 2 oder 3 × 3 Kontrollpunkten scheitert

Crate: kernel-smlib (nurbs_surface)
surface(points = [[[0, 0, 0], [20, 0, 6]], [[0, 20, 6], [20, 20, 0]]]);

„surface gescheitert: SmApiCreateSurfaceFromOrderedPoints failed: SM_ERR (1001)“, ebenso für 3 × 3. cad-eval nimmt ab 2 × 2 Punkte an, die Spec nennt kein Minimum; 4 × 4 funktioniert. Vorschlag: Grad an die Punktzahl anpassen (wie interp_curve bei drei Pfadpunkten).

F3 Nahtkanten zählen als eigene Kanten eines Primitivs

Crate: cad-engine ($fillet / $chamfer)
cylinder(h = 10, r = 5, $chamfer = 1);   // „3 Kanten“
sphere(5, $fillet = 1);                    // Fehler

Beim Zylinder werden Deckel-, Boden- und die Nahtkante ausgewählt („3 Kanten“, gezeichnet 3); bei der Kugel nur die Naht („1 Kante“), und die Verrundung scheitert mit „fillet: none of the edges can be blended (smooth, seam or open edges)“ – Zeile rot statt „0 Kanten“ bzw. ohne Wirkung. Glatte Naht- und Polkanten sollten nicht ausgewählt werden.

C16 Achsgebundenes Ziehen

Mit gedrückter Umschalttaste bestimmt die Mausbewegung die Achse (die Achse des lokalen Systems, deren Bildschirmrichtung am besten zur Bewegung passt); der Griff läuft auf einer Linie in Achsfarbe, nur diese Komponente ändert sich – y = 5.5 und z = 2.25 bleiben als Text erhalten (cad-eval schreibt unveränderte Literale nicht neu).
