1. Scope

  • Facade (smlib/facade, ABI version 2 → 3): the new query sc_brep(h) returns topology (bodies → shells → faces → loops → oriented edges, vertices) and exact geometry: every face and edge as NURBS (degree, knots, weights, control points), analytic surfaces (plane, cylinder, cone, sphere, torus, surface of revolution, extrusion surface) additionally with their parameters. Non-B-spline geometry (blends, offsets) would be approximated to the model tolerance and flagged. Native side (FFI) and Wasm bridge (smlib-bridge.js, exports.txt).
  • Neutral B-rep cad_kernel::brep with Kernel::brep (default: Unsupported). kernel-smlib checks the analytic parameters against the NURBS (9×9 samples), trims edge curves to their interval (knot insertion), detects exact lines and circles and determines same_sense from SMLib's normal at an interior face point.
  • Writer cad-step (kernel-independent): AP242 (default) or AP214, product structure (PRODUCT … SHAPE_DEFINITION_REPRESENTATION), units mm and degrees, MANIFOLD_SOLID_BREP/BREP_WITH_VOIDS per body (several shells → several solids), open surfaces as SHELL_BASED_SURFACE_MODEL, colors from color() as STYLED_ITEM per face.
  • Integration: Engine::export_step, cad export -o x.step [--schema ap214] (JSON with volume, area, bounding box and statistics), session Export{format:"step"} (additive, protocol.ts regenerated), Wasm.
  • Verification tests/step/verify.py: reads every file with OpenCASCADE (not our code), BRepCheck_Analyzer, closed shells, number of solids/faces, volume and bounding box against the kernel (relative 0.0001), area (0.0005, see section 7). Rust tests of the writer (syntax, references, numbers read back with our own Part 21 reader) run without Python.
  • solidcore: crate kernel-solidcore, CLI cad diff-kernels, documentation docs/solidcore-umstieg.md.

Why AP242: AP242 is the current edition that merges and replaces AP203 and AP214; the B-rep entities (Part 42) are the same in both, the choice only changes the header and the application context. AP214 remains available via --schema ap214 for older readers that do not know the AP242 schema name.

Rendered with the CLI's software rasterizer (cad-render, example render_stl). The images therefore show the geometry as seen by a different kernel.

7. Known limitations

  • Area: SMLib integrates areas only to about 1e-4 (SmApiBrepComputeArea clamps the accuracy to [1e-4, 1e-1]). For freiformdeckel the kernel area deviates by 1.9e-4; OCCT adaptive (6658.641 mm²) and a fine OCCT mesh (6658.656 mm²) agree with each other, so the error lies in the kernel reference value. The area check therefore uses 5e-4, volume and bounding box 1e-4.
  • OCCT's default integration (fixed Gauss rule) deviates by up to 1e-4 for B-spline surfaces and surfaces of revolution; verify.py integrates adaptively (1e-9).
  • No p-curves (2D curves in the surface parameter space): readers project the 3D edges. OCCT does this without errors for all examples; other systems might read B-spline surfaces with a seam more slowly.
  • Edge curves of booleans are B-splines (intersection curves); exact circles/lines are detected (tolerance 1e-9 of the model size), ellipses only if SMLib holds them as such (none in the examples).
  • Surfaces without a B-spline form (blend, offset surfaces) would be approximated; in all examples SMLib supplies exact B-splines or analytic surfaces (0 approximated).
  • Voids (BREP_WITH_VOIDS) are checked in the Rust test and on the kernel (sphere minus sphere); none occur in the examples.
  • Colors: per face from color() as STYLED_ITEM; OCCT reads them only via XCAF, verify.py does not check them.
  • The root is exported in its own coordinate system (like STL/3MF); 2D results are rejected.
  • In the browser the session writes a fixed timestamp (1970-01-01T00:00:00), the CLI the current UTC time.
  • solidcore: see section 6; kernel-solidcore only covers the API entry points available today.
