3 Fehler: Ursache, Korrektur, Nachweis

F1 shell eines verrundeten Körpers

Ursache
Nicht die Vorprüfung „no cavity“ (sie betrifft nur ebene, gegenüberliegende Wände; die Meldung „leaves no cavity“ kam nach SMLib, das einen offenen Körper zurückgab). SMLibs Schalenbildung mit geöffneter Fläche (SmApiShellBrepFull → SmOffsetExecutive::ShellBrep, Zweig mit Öffnung über SmMerge) trägt an verrundeten Körpern nicht: je nach Optionen SM_ERR_NULL_POINTER in SmMerge.cpp:672, ein offener Körper aus den 26 Eingangsflächen, oder ein geschlossener Körper, dessen Randflächen fehlen und dessen innere Rundungen durch verlängerte Flächen ersetzt sind (11–15 Flächen fallen in der Gültigkeitsprüfung durch, Volumen 0,08 % daneben). Welcher Fall eintrat, hing an der Adressreihenfolge von SMLibs Zeigertabellen (daher nativ und Wasm verschieden). Der geschlossene Innenversatz desselben Körpers (SmApiOffsetBrepFull, −t) ist dagegen exakt (Volumen = Minkowski-Formel auf 10−7).
Korrektur
sc_shell versucht SMLibs Schale; scheitert sie oder überlappt sie sich, baut die Fassade die Schale aus Booleans: Körper − O − P1 − … − Pk, O der geschlossene Innenversatz, Pi ein Prisma über der Versatzfläche jeder geöffneten (ebenen) Fläche, von knapp innerhalb des Hohlraums bis über den Körper hinaus (aufgedickte Einzelfläche). Die Seitenwände des Prismas gehen durch den Rand der Versatzfläche: der Öffnungsrand ist das Band zwischen geöffneter Fläche und ihrem Versatz, wie bei SMLibs eigener Schale. Booleans über die geprüften Booleans der Fassade, Ergebnis mit der Gültigkeitsprüfung. Zusätzlich Patch 0001 (1ed8669): SMLibs Zeigertabellen geben Schlüssel in Einfügereihenfolge aus – Ergebnisse hängen nicht mehr von der Heap-Lage ab.
Nachweis
Volumen gegen die geschlossene Form (abgerundeter Quader minus innerer abgerundeter Quader mit r − t minus Wandband unter der ebenen Deckfläche), STEP-Prüfung, gleiche Szenen nativ und Wasm (Abschnitt 5), Rust-Tests shell_of_rounded_boxes, dose_shell_example_is_a_hollow_box, shell_of_a_rounded_box_open_at_the_top, Node-Test, Playwright E03.

F4 fase_chamfer.scad: union(chamfer) wählte acht Kanten

Ursache
„Neue Kanten“ einer Booleschen Operation waren Kanten zwischen Flächen verschiedener Operanden (Flächen-Tags). Teilen sich zwei Operanden eine Ebene (Platte und Turm mit gleicher Vorder- und Rückseite), verschmilzt SMLib die Flächen zu einer mit dem Tag eines Operanden; die sechs alten Turmkanten an Vorder- und Rückseite trennten dann Flächen verschiedener Operanden und galten als neu. Die Fase an diesen Kanten scheiterte (SM_ERR).
Korrektur
Eine Kante, die auf einer Kante eines Operanden liegt, ist nicht neu (Abtastpunkte auf dem Kantenzug eines Operanden, Toleranz 10−6 der Modellgröße).

4 Variabler Radius

Architektur: auswertbare Beschreibung statt Rückruf

Die Kanten, an denen der Radius gebraucht wird, gibt es erst, wenn der Kernel den Körper gebaut hat – lange nach der Auswertung, in der Engine. Zwei Wege: ein Rückruf aus der Engine in die Auswertung, oder die Auswertung liefert eine auswertbare Beschreibung der Funktion. Gewählt ist die Beschreibung: cad-eval übersetzt das Funktionsliteral in ein Radiusgesetz (cad_ir::Law), einen kleinen reinen Ausdruck über p. Was nicht von p abhängt (eingefangene Variablen, Rasterebenen, Listenausdrücke, beliebige Builtins), wird dabei schon ausgewertet und ist Konstante; Aufrufe von Benutzerfunktionen und Funktionswerten werden eingesetzt (Parameter als lokale Slots, Tiefe ≤ 16); übrig bleiben Literale, Arithmetik, Vergleiche, && || ! ?:, let, Indizes, .x/.y/.z, Vektoren und die Mathe-Builtins (sin … lookup).

  • Das Gesetz ist Teil des Baums (serialisierbar, Teil des Cache-Schlüssels): eine geänderte eingefangene Variable ändert den Schlüssel, gleicher Quelltext trifft den Cache. Ein Rückruf bräuchte dafür einen eigenen Schlüssel der Closure samt Umgebung.
  • Die Engine hängt weiter nicht von cad-eval und dessen AST-Lebensdauer ab; Wasm und nativ werten dasselbe Datenobjekt aus, auch aus dem Cache, ohne erneute Auswertung des Quelltexts.
  • Grenze: nur der reine Ausdruckskern ist von p abhängig möglich (keine Texte, keine Listenausdrücke über p, keine Rekursion über p); solche Fälle sind Fehler an der Funktion mit eigener Meldung.

Ablauf

  1. Auswertung: fillet(r = function …) → Op::Blend { law }, difference(fillet = function …) → Op::Boolean { fillet_law }. chamfer und $fillet mit Funktion: Warnung, nicht unterstützt.
  2. Engine: Kantenwahl wie beim konstanten Radius (Zonen, neue Kanten, ohne glatte Kanten); je Kante m Stützpunkte (etwa einer je 1,5 mm, 4 bis 32) von Kernel::law_stations; das Gesetz im System der fillet-/Boolean-Anweisung an jedem Stützpunkt ausgewertet. Radius ≤ 0, keine Zahl → Fehler mit Wert und Position, Kante rot, Körper unverändert. Alle Werte gleich → konstante Verrundung (gleiches Ergebnis wie fillet(r)). Sonst Kernel::fillet_variable; Kernelfehler wie beim konstanten Radius mit dem Bereich („Verrundung gescheitert (8–18 mm): …“). Hinweis am Zeilenende: „r min–max“ der Stützwerte.
  3. Fassade (sc_law_stations, sc_fillet_var): das Gesetz einer Kante ist ein geklemmter B-Spline vom Grad min(3, m − 1) über dem normierten Kantenparameter mit gleichmäßigen inneren Knoten, Kontrollradius j am Greville-Punkt tj (dort liegen die Stützpunkte). Er bleibt zwischen kleinstem und größtem Wert, ist exakt für konstante und lineare Verläufe und nimmt an den Kantenenden den ersten und letzten Wert an. Als SmBSplineFilletLaw trägt die Gesetzeskurve den Radius als x und t selbst als y (Kontrollpunkte (rj, tj), also y(t) = t), damit SMLib sie an Ecken über die Kantenenden hinaus verlängern kann. Je Kante SMLibs Variabler-Radius-Löser (SM_FS_VARIABLE_RADIUS), Kanten mit gleichen Werten der konstante.

8 Grenzen

  • shell aus Booleans nur für ebene geöffnete Flächen (das Prisma ist die aufgedickte Versatzfläche); bei gekrümmten geöffneten Flächen bleibt SMLibs Ergebnis bzw. dessen Fehlermeldung. Geschlossene Schalen (ohne Zone) nehmen weiter SMLibs Ergebnis, wenn es gültig ist. Die Booleans kosten Zeit: dose_shell 988 ms (scheiternd) → 1925 ms (Abschnitt 6); in smlib.wasm (Node-Test, 90 × 34 × 18, r 3) 1758.4 ms.
  • Wanddicke ≥ Rundungsradius (r ≤ t, z. B. 30 × 20 × 10 mit r 1, Wand 2): der Innenversatz wäre scharfkantig; SMLibs Versatz scheitert dort in 7eba8aa (SM_ERR, Fork-Commit a252570 nicht übernommen), die Schale bleibt wie vorher ein Fehler (Meldung nennt beide Wege).
  • Variabler Radius: SMLibs Variabler-Radius-Löser ist empfindlich. Steile Verläufe mit großem Radius an Taschenecken scheitern („überlappt sich“, z. B. Taschenrand mit 1 + p.x/20, 1,25–2,75), ebenso Kreiskanten mit veränderlichem Radius (SM_ERR); das Beispiel nutzt deshalb 1 + p.x/40. Sprünge (p.z < 10 ? 2 : 4 an senkrechten Kanten) werden über etwa drei Stützpunktabstände geglättet; der Hinweis zeigt den Bereich der Stützwerte (lookup-Spitze 4 → „3.9“, weil kein Stützpunkt genau auf x = 20 liegt). Position p im System der fillet-/Boolean-Anweisung. Kein variabler Radius für chamfer und $fillet (Warnung).
  • Glatte Kanten: SMLibs Kriterium (Flächen innerhalb 2° tangential) – fast tangentiale Kanten werden nie gewählt. Die Prüfung „alte Kante eines Operanden“ (F4) vergleicht mit den Kantenzügen der Operanden, für gekrümmte Kanten nur so genau wie deren Abtastung (dort bleibt die frühere Wahl).
  • SMLib-Patch als Arbeitskopie-Patch über 7eba8aa (der Fork-Commit liegt nicht auf capi-tess); vorgebaute Bibliotheken (SMLIB_PREBUILT) müssen mit dem Patch neu gebaut werden (Header-Änderung, sonst ODR-Bruch). Ein Symlink third_party/smlib wird von fetch.sh nur geprüft.

E01 Variabler Radius im Browser

Code
// unter der Mitte Radius 2, darüber 4; die senkrechten Kanten gehen stetig von 2 auf 4
fillet(r = function (p) p.z < g.mitte ? 2 : 4) {
    box(g[links, vorne, boden], g[rechts, hinten, deckel]);
}

// Tasche mit verrundetem Rand, der Radius wächst entlang x (1,125 bis 1,875 am Rand)
translate([60, 0, 0]) difference(fillet = function (p) 1 + p.x / 40) {
    cube([40, 30, 10]);
    translate([5, 8, 4]) cube([30, 14, 10]);
}

// nur die vier Deckelkanten, Radius aus einer Tabelle (lookup) über x
translate([120, 0, 0]) fillet(r = function (p) lookup(p.x, [[0, 1.5], [20, 4], [40, 1.5]])) {
    box(g[links, vorne, boden], g[rechts, hinten, deckel]);
    zone(g.deckel, d = 1);
}

variabler_radius.scad: der Radius ist eine Funktion der Position. Am Zeilenende stehen Kantenzahl und Radiusbereich der ausgewerteten Stützpunkte („12 Kanten · r 2–4“, „4 Kanten · r 1.125–1.875“, „1 Zone · 4 Kanten · r 1.5–3.9“); ausgewählte Kanten orange, Zone blau wie beim konstanten Radius.

E02 Fehlerfälle des variablen Radius

Code
fillet(r = function (p) p.x - 5) {
    cube(20);
}
translate([40, 0, 0]) fillet(r = function (p) 8 + p.z / 2) {
    cube(20);
}

Radius ≤ 0 an einem Stützpunkt: Zeile rot, Meldung mit Wert und Position, die Kante rot, der Würfel bleibt ohne Verrundung (12 Dreiecke). Zu großer Radius: Kernel-Meldung mit dem Radiusbereich, Körper unverändert – wie beim konstanten Radius.

E03 shell verrundeter Körper

Code
grid g { z: o = 18; }
grid h { z: o = 30; }
shell(1.6) { box([0, 0, 0], [90, 34, 18], $fillet = 3); zone(g.o, d = 1); }
translate([0, 45, 0]) shell(1.6) { box([0, 0, 0], [90, 34, 18], $fillet = 5); zone(g.o, d = 1); }
translate([0, 90, 0]) shell(1.5) { box([0, 0, 0], [50, 35, 30], $fillet = 4); zone(h.o, d = 1); }

dose_shell.scad ist wieder grün: ein geschlossener Hohlkörper mit Öffnung oben, „1 Zone · 1 Fläche geöffnet“. Die drei Fälle aus Bericht 4 (früher SM_ERR_NULL_POINTER, „leaves no cavity“, „self-overlapping“) ergeben Hohlkörper.

E04 Naht- und Polkanten

Code
cylinder(h = 10, r = 5, $chamfer = 1);
translate([20, 0, 0]) sphere(5, $fillet = 1);
translate([40, 0, 0]) fillet(1) { cylinder(h = 10, r = 5); sphere(20); }

Die Naht des Zylinders und die Naht/Pole der Kugel sind glatt und werden nie ausgewählt: $chamfer am Zylinder „2 Kanten“ (vorher 3), $fillet an der Kugel „0 Kanten“ als Warnung ohne Wirkung (vorher Fehler), Zonenauswahl um den ganzen Zylinder ebenfalls 2 Kanten.
