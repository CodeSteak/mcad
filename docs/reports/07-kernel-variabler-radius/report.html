3 Bugs: cause, fix, evidence

Diagnostic and hint texts in the tables below are quoted verbatim from the program output (German by design; "Z." = line, "Fehler" = error, "Warnung" = warning, "Kanten" = edges, "gescheitert" = failed).

F1 shell of a filleted body

Cause
Not the "no cavity" pre-check (it only concerns planar, opposite walls; the message "leaves no cavity" came after SMLib had returned an open body). SMLib's shell construction with an opened face (SmApiShellBrepFull → SmOffsetExecutive::ShellBrep, branch with opening via SmMerge) does not hold up on filleted bodies: depending on the options, SM_ERR_NULL_POINTER in SmMerge.cpp:672, an open body made of the 26 input faces, or a closed body whose border faces are missing and whose inner roundings are replaced by extended faces (11–15 faces fail the validity check, volume off by 0.08 %). Which case occurred depended on the address order of SMLib's pointer maps (hence different natively and in Wasm). The closed inward offset of the same body (SmApiOffsetBrepFull, −t), in contrast, is exact (volume = Minkowski formula to 10−7).
Fix
sc_shell tries SMLib's shell; if it fails or self-overlaps, the facade builds the shell from booleans: body − O − P1 − … − Pk, O being the closed inward offset, Pi a prism over the offset face of each opened (planar) face, from just inside the cavity to beyond the body (thickened single face). The side walls of the prism go through the border of the offset face: the opening border is the band between the opened face and its offset, as with SMLib's own shell. Booleans go through the facade's checked booleans, the result through the validity check. In addition patch 0001 (1ed8669): SMLib's pointer maps return keys in insertion order – results no longer depend on the heap layout.
Evidence
Volume against the closed form (rounded cuboid minus inner rounded cuboid with r − t minus the wall band under the planar top face), STEP check, identical scenes native and Wasm (section 5), Rust tests shell_of_rounded_boxes, dose_shell_example_is_a_hollow_box, shell_of_a_rounded_box_open_at_the_top, Node test, Playwright E03.

F2 surface(points) with 2 × 2 or 3 × 3 points

Cause
SmApiCreateSurfaceFromOrderedPoints calls SmBSplineSurface::ApproximatePoints with a fixed degree 3 in both directions; that requires at least 4 points per direction, otherwise SM_ERR.
Fix
sc_nurbs_surface calls ApproximatePoints itself, with degree min(3, n − 1) separately per direction: bilinear for 2, quadratic for 3, cubic from 4 (unchanged from 4 × 4). With as many control points as points, the least-squares fit interpolates the points.
Evidence

F3 Seam and pole edges counted as edges

Cause
For $fillet/$chamfer the engine selected all edges of the primitive, and in zones all edges in the zone. SMLib's cylinder has a seam (same face on both sides), the sphere a seam from pole to pole. The facade skipped such edges when filleting (GetBlendEdgeuse() == NULL), but they were still counted and drawn; for the sphere no edge remained → error.
Fix
sc_edges reports flags per edge, SC_EDGE_SMOOTH = nothing to fillet (seam, pole, tangentially continuous transition within 2°, open border; SMLib's own criterion). EdgeInfo.smooth; the engine never selects such edges – for $fillet/$chamfer, in zones and for fillet = on booleans. A primitive without an edge to fillet yields "0 edges" as a warning without effect. The tangent borders of earlier roundings no longer count either (nested blocks).

F4 fase_chamfer.scad: union(chamfer) selected eight edges

Cause
"New edges" of a boolean operation were edges between faces of different operands (face tags). If two operands share a plane (plate and tower with the same front and back face), SMLib merges the faces into one with the tag of one operand; the six old tower edges on the front and back then separated faces of different operands and were considered new. The chamfer on these edges failed (SM_ERR).
Fix
An edge that lies on an edge of an operand is not new (sample points on the edge chain of an operand, tolerance 10−6 of the model size).

4 Variable radius

Architecture: evaluable description instead of a callback

The edges at which the radius is needed only exist once the kernel has built the body – long after the evaluation, in the engine. Two options: a callback from the engine into the evaluation, or the evaluation supplies an evaluable description of the function. The description was chosen: cad-eval translates the function literal into a radius law (cad_ir::Law), a small pure expression over p. Whatever does not depend on p (captured variables, grid planes, list comprehensions, arbitrary builtins) is evaluated at that point and becomes a constant; calls to user functions and function values are inlined (parameters as local slots, depth ≤ 16); what remains are literals, arithmetic, comparisons, && || ! ?:, let, indices, .x/.y/.z, vectors and the math builtins (sin … lookup).

  • The law is part of the tree (serializable, part of the cache key): a changed captured variable changes the key, the same source hits the cache. A callback would need its own key for the closure including its environment.
  • The engine still does not depend on cad-eval and its AST lifetime; Wasm and native evaluate the same data object, also from the cache, without re-evaluating the source.
  • Limitation: only the pure expression core can depend on p (no strings, no list comprehensions over p, no recursion over p); such cases are errors at the function with their own message.

Procedure

  1. Evaluation: fillet(r = function …) → Op::Blend { law }, difference(fillet = function …) → Op::Boolean { fillet_law }. chamfer and $fillet with a function: warning, not supported.
  2. Engine: edge selection as for the constant radius (zones, new edges, without smooth edges); per edge m stations (about one per 1.5 mm, 4 to 32) from Kernel::law_stations; the law is evaluated at each station in the coordinate system of the fillet/boolean statement. Radius ≤ 0 or not a number → error with value and position, edge red, body unchanged. All values equal → constant fillet (same result as fillet(r)). Otherwise Kernel::fillet_variable; kernel errors as for the constant radius, with the range ("Verrundung gescheitert (8–18 mm): …"). Hint at the end of the line: "r min–max" of the station values.
  3. Facade (sc_law_stations, sc_fillet_var): the law of an edge is a clamped B-spline of degree min(3, m − 1) over the normalized edge parameter with uniform interior knots, control radius j at the Greville point tj (that is where the stations lie). It stays between the smallest and largest value, is exact for constant and linear profiles and takes the first and last value at the edge ends. As SmBSplineFilletLaw, the law curve carries the radius as x and t itself as y (control points (rj, tj), i.e. y(t) = t), so that SMLib can extend it beyond the edge ends at corners. Per edge SMLib's variable-radius solver (SM_FS_VARIABLE_RADIUS), edges with equal values use the constant one.

8 Limitations

  • shell from booleans only for planar opened faces (the prism is the thickened offset face); for curved opened faces SMLib's result or its error message remains. Closed shells (without a zone) still use SMLib's result if it is valid. The booleans cost time: dose_shell 988 ms (failing) → 1925 ms (section 6); in smlib.wasm (Node test, 90 × 34 × 18, r 3) 1758.4 ms.
  • Wall thickness ≥ rounding radius (r ≤ t, e.g. 30 × 20 × 10 with r 1, wall 2): the inward offset would be sharp-edged; SMLib's offset fails there in 7eba8aa (SM_ERR, fork commit a252570 not adopted), and the shell remains an error as before (the message names both approaches).
  • Variable radius: SMLib's variable-radius solver is sensitive. Steep profiles with a large radius at pocket corners fail ("self-overlapping", e.g. pocket border with 1 + p.x/20, 1.25–2.75), as do circular edges with a varying radius (SM_ERR); the example therefore uses 1 + p.x/40. Jumps (p.z < 10 ? 2 : 4 on vertical edges) are smoothed over about three station spacings; the hint shows the range of the station values (lookup peak 4 → "3.9", because no station lies exactly at x = 20). Position p in the coordinate system of the fillet/boolean statement. No variable radius for chamfer and $fillet (warning).
  • Smooth edges: SMLib's criterion (faces tangent within 2°) – nearly tangent edges are never selected. The check "old edge of an operand" (F4) compares with the edge chains of the operands, for curved edges only as accurately as their sampling (there the earlier selection remains).
  • SMLib patch as a working-copy patch on top of 7eba8aa (the fork commit is not on capi-tess); prebuilt libraries (SMLIB_PREBUILT) must be rebuilt with the patch (header change, otherwise ODR violation). A symlink third_party/smlib is only checked by fetch.sh.
