1 Scope and architecture

The desktop version runs the same React app as the browser; new are the Tauri app (crates/cad-app), the backend without Tauri (crates/cad-desktop: engine process with supervisor, binary format, files, watcher, Git), the local IPC (crates/cad-ipc) and, in the web app, TauriTransport, the desktop platform and the section view (browser and desktop).

cad datei.scad  (app process, feature gui)
  Main thread: Tauri event loop + webview (React app, TauriTransport instead of worker)
  Commands: engine_post · open/save/save_as · watch_files · git_hunks · ui_reply · …
  Channel (Tauri 2, raw): binary batches  ◀────────── stdout ── cad engine-host (engine process)
  Supervisor (cad-desktop::engine) ───── stdin: post [ToEngine…] ─▶  engine thread 256 MiB stack:
    Watchdog 15 s: kill process + restart, BlockKeys                 Session::post / step(16 ms)
  cad-watch: notify → file-changed / file-removed                    SMLib native (FFI)
  cad-ui-ipc: Unix socket ui-<pid> (cad-ipc) ◀── cad ui status | show | screenshot
  • Engine: native cad-session with natively linked SMLib in a separate process (cad engine-host, the same binary), containing an engine thread with a 256 MiB stack and the same loop as the worker (post messages, a SetSource followed by another one is dropped, then step(16 ms), new messages in between). A process rather than just a thread, because SMLib and its C facade have global state (handle table, messages): a hanging call can only be ended together with the process; a replacement thread next to it would share the state. The watchdog in the app process counts sent and accepted messages (seen) and replaces the engine after 15 s without a response, with the same BlockKeys/SetFiles/SetContext/SetSource as WorkerTransport.
  • Transport: EngineTransport stays; TauriTransport bundles UI messages per microtask into one engine_post command (order is kept) and receives batches over a Tauri 2 channel as ArrayBuffer: [u32 Kopflänge][u32 Datenlänge][Kopf-JSON][Daten] (header length, data length, header JSON, data), mesh arrays as {"$b": [offset, länge, typ]}, typed-array views without copying in the webview. The desktop UI is built without worker and Wasm (pnpm build:tauri) and embedded in the binary.
  • One binary: cad with feature gui (default). cad, cad datei.scad, cad ordner/ start the UI; without DISPLAY/WAYLAND_DISPLAY or without gui: message listing the headless commands, exit 2. All subcommands remain.
  • IPC (cad-ipc, reusable): endpoints as Unix sockets in $CAD_IPC_DIR, else $XDG_RUNTIME_DIR/controller-cad, else $TMPDIR/controller-cad-<uid> (folder 0700, owner checked, sockets 0600, peer UID checked); frames with version field v, kinds request/response/event, binary part; stale sockets (connection refused) are removed on bind, connect and list. API: Server::bind(name), Server::serve(handler), connect(name), Conn::request/request_with/respond/send_event/next_event, list(prefix).

5 3D section view

Tool "Section" (German UI: „Schnitt“) in the view (browser and Tauri): plane X/Y/Z through the model center or free (normal from the view direction or entered), handle (blue dot) for dragging along the normal with snapping to grid planes of the context module and to anchors (Alt: free, 0.1 mm), flip, filled cap and contour. Method as in the CLI renderer: clipping plane on all model materials, per opaque body one parity pass (stencil INVERT over all fragments of the clipped mesh) and a large quad in the plane that draws the cap where the bit is set (depth-tested, hatched, direction alternating per body). Convention exactly as cad render --section: plane through p with normal n, the side n points into is removed; "Copy as cad render …" writes --section a=v [--section-flip] or --section-plane p,n with --module and the camera (--azimuth/--elevation).

8 Known limitations

  • Control IPC only on Unix (Linux, macOS); on Windows cad-ipc reports "not implemented" (named pipes missing), the app itself is untested there. One window per app process; cad datei.scad starts another process instead of using the running window (cad ui show does that).
  • Watchdog tests block the engine process via a test message; a real hanging SMLib call was not reproduced. The block lasts until the app is restarted.
  • Watcher: renaming appears as deletion (bar "deleted or renamed"), the new name is not tracked; an external change to exactly the content of the UI goes unnoticed (intended).
  • Git only against HEAD (not against the index), via the git command; without git no markers.
  • Native dialogs (Open, Folder, Save as) are not automated in the E2E tests; tested are opening via the command line, cad ui show, recently opened (Rust) and saving.
  • Section: one plane; caps only for opaque, closed bodies; contour on the CPU per position; handles, grids and anchors are not clipped. The copied CLI call reproduces section and view direction, not the framing (UI perspective, CLI orthographic).
  • Measurements without GPU (Xvfb/llvmpipe, SwiftShader).
