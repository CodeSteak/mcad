1 Task and result

Three user requests: multiple colors with an export that Bambu Studio prints "fairly easily with several filaments"; replace the CSS colors with a small, good-looking preset (English names only, muted tones, warning and random color for unknown names); a thoroughly reworked dark theme. Implemented:

  • Palette with 16 colors in cad-eval (one source, generated for the UI), unknown names → warning „Farbe x unbekannt – Zufallsfarbe“ ("color x unknown – random color") and a stable color from the hash of the name; hex, vectors and alpha exact (section 2).
  • Color regions: each part is split via kernel booleans into bodies per color (cached), sum of the volumes = part volume; filament slots from color("teal", filament = 2) or automatic (section 3).
  • 3MF for Bambu Studio / OrcaSlicer: one object per part, one sub-part per color at the same origin, color group and Metadata/model_settings.config with extruder per sub-part – the format worked out from the slicers' source code (section 5), checked with lib3mf, trimesh, a model of the Bambu importer and PrusaSlicer (section 6). In addition "one STL per color" as a ZIP. CLI: cad export -o x.3mf is multi-color (--single-color), cad outline and cad measure --colors show colors, slots, volume and mass.
  • UI: "Colors & filaments" (German UI: „Farben & Filamente“) (swatch, name, lines, slot selector that writes filament = n into the code, volume and mass for PLA 1.24 g/cm³), color per face in the view, "Show color regions" (German UI: „Farbregionen zeigen“) (section 7).
  • Dark theme: choice System (default, follows prefers-color-scheme, also in Tauri)/Light/Dark, token set with WCAG check (text ≥ 4.5:1), editor components with their own default theme adapted, palette colors slightly lightened in the dark theme; cad render --theme dark (section 8).

2 Palette

The names chosen are those that occur most often in OpenSCAD files – in the corpus of OpenSCAD examples and libraries in the container red (11), green (7), cyan (7), yellow, gray, blue, black (2 each), magenta, lime; from experience with widely used projects additionally white, orange, silver, purple – plus teal, pink, brown as common filament colors. The proposal indigo/slate was dropped: indigo lies between blue and purple (hard to separate with deuteranopia), slate between gray and blue; silver and magenta are more frequent in OpenSCAD files. grey, aqua, fuchsia are the CSS spellings of gray, cyan, magenta; there are no German names.

Values: target values in OKLCH (lightness L, chroma C ≤ 0.18 – muted, no pure RGB corners –, hue h), optimized by a search for the smallest distance in OKLab for normal vision and for simulated deuteranopia and protanopia (Machado, Oliveira, Fernandes 2009, severity 1.0, in linear sRGB). The formulas are in palette.rs; cargo test -p cad-eval --test palette enforces the minimum distances, tools/palette/palette.py recomputes the same values.

3 Rules: color regions and filaments

Color regions (volume per color)

  • The body of a colored subtree belongs to its color: the result of the color() node, placed in the coordinate system of the part (local matrices and resize factors along the path).
  • If colors overlap, the later statement wins, the earlier one is reduced by it; "later" means pre-order in the tree: an inner color() after the outer one, a later sibling after the earlier one.
  • Subtracted material applies to all: each piece is intersected with the result (difference removes the hole from all colors); colors that occur only in subtracted operands get no slot.
  • Material in no colored subtree (e.g. the fillet between two colors) belongs to the color on the part, else to the default entry (if the part has uncolored primitives), else to the first color of the part.
  • Computation: Stück(C) = R ∩ M(C) − ⋃ M(später) (piece of C = result ∩ material of C − union of later materials), remainder R − ⋃ M, pieces of one color united, empty ones dropped; about three booleans per color node. Result per part is a list (color, slot, body) with volume; if the sum differs from the part volume, the engine warns („Farbregionen ungenau“, "color regions inaccurate"). Cached by part, color nodes, placements and colors; color and slot are not part of the node keys – a new color or a new slot recomputes no node (test regions_are_cached…). Without color nodes below the part there is no boolean: one region from the bodies of the part, volume = cached part volume (test uncoloured_part_needs_no_boolean).

Filament slots

  • color("teal", filament = 2) sets the slot of the color (1–16, named argument; the first specification applies, a contradiction warns).
  • Material without color() ("default", #c3c8cf) prints with slot 1.
  • All other colors get the lowest free slot in the order of their first occurrence. The same color in another spelling ("gray", "GREY", "#7b7d81") is the same entry.
  • Changing the slot in the UI = text edit (SetFilament): every color() statement of the color with filament = … gets the new value, otherwise the first one gets , filament = n; "automatic" removes the argument. Reason: the code stays the only source (CLI export and UI export agree, the agent sees the same), undo and the Git gutter capture the change; a preview override as in the parameter bar would be lost on saving and would be a second source of truth for the export.

// Zweck: Mehrfarbig drucken (Bericht 11) – Türschild mit Schrift-Relief und Spielfigur als
// zwei Bauteile, Farben aus der Palette, ein fester Filament-Slot; Export als 3MF mit einem
// Teil je Farbe für Bambu Studio / OrcaSlicer.

// Blockbuchstaben aus Balken: s = Strichstärke, b × h = Feld des Buchstabens.
module balken(x, y, w, h, t) translate([x, y, 0]) cube([w, h, t]);

module buchstabe(c, b = 8, h = 12, s = 2, t = 1.2) {
    if (c == "C") {
        balken(0, 0, s, h, t);
        balken(0, h - s, b, s, t);
        balken(0, 0, b, s, t);
    } else if (c == "A") {
        balken(0, 0, s, h, t);
        balken(b - s, 0, s, h, t);
        balken(0, h - s, b, s, t);
        balken(0, h / 2 - s / 2, b, s, t);
    } else if (c == "D") {
        // Balken überlappen (nur Kanten berühren gäbe keinen geschlossenen Körper)
        balken(0, 0, s, h, t);
        balken(0, h - s, b - s / 2, s, t);
        balken(0, 0, b - s / 2, s, t);
        balken(b - s, s / 2, s, h - s, t);
    }
}

module schild(w = 60, d = 28, t = 3, rand = 2.5) {
    grid g {
        x: links = 0, schrift = 15, rechts = w;
        y: vorne = 0, zeile = 8, hinten = d;
        z: boden = 0, oben = t;
    }
    difference() {
        union() {
            // Grundplatte weiß, Rahmen petrol (sitzt auf der Platte)
            color("white") box(g[links, vorne, boden], g[rechts, hinten, oben]);
            color("teal") difference() {
                box(g[links, vorne, oben] - [0, 0, 0.5], g[rechts, hinten, oben] + [0, 0, 1]);
                box(g[links, vorne, oben] + [rand, rand, -1], g[rechts, hinten, oben] - [rand, rand, -2]);
            }
            // Schrift-Relief rot, auf Filament 3 festgelegt
            color("red", filament = 3)
                for (i = [0:2]) translate(g[schrift, zeile, oben] + [i * 11, 0, -0.2]) buchstabe(["C", "A", "D"][i]);
        }
        // Aufhängebohrung: abgezogen, gilt für alle Farben
        translate(g[links, hinten, boden] + [6, -6, -1]) cylinder(h = t + 3, r = 1.6);
    }
}

module spielfigur(r = 9, h = 26) {
    grid p {
        x: achse = 0, hals = r * 0.3, rand = r * 0.85, fuss = r;
        y: boden = 0, sockel = 4, mitte = h * 0.55, kopf = h * 0.8;
    }
    // Profil: vom Rand des Sockels zum Hals (quadratisch), dann gerade bis zum Kopf
    z0 = p.sockel - 1;
    profil = concat(
        [[0, z0]],
        [for (i = [0:16]) let (t = i / 16) [p.hals + (p.rand - p.hals) * (1 - t) * (1 - t), z0 + t * (p.mitte - z0)]],
        [[p.hals, p.kopf], [0, p.kopf]]);
    color("blue") {
        cylinder(h = p.sockel, r = p.fuss);
        rotate_extrude() polygon(profil);
    }
    // weißer Kragen und gelber Kopf: spätere Anweisungen gewinnen bei Überlappung
    color("white") translate([0, 0, p.mitte - 1]) cylinder(h = 2, r = r * 0.5);
    color("yellow") translate([0, 0, p.kopf + 2.5]) sphere(r * 0.42);
}

// Spielfigur neben dem Schild (eigenes Bauteil = eigenes Objekt im Slicer)
module figur(at = [80, 14, 0]) translate(at) spielfigur();

schild: schild();
figur: figur();

Assumptions and their sources

Read in the source code of Bambu Studio (bambulab/BambuStudio, branch master) and OrcaSlicer (SoftFever/OrcaSlicer, branch main), retrieved on 2026-10-23 via raw.githubusercontent.com (checksums below):

  1. Foreign 3MF: Bambu Studio treats a file as its own only if Application starts with "BambuStudio-" (_handle_end_metadata, OrcaSlicer additionally "OrcaSlicer-"). We do not pose as Bambu Studio; the file is loaded as "From_Other" (Model::read_from_archive; PrusaSlicer files are recognized by PrusaFileParser from the name "PrusaSlicer").
  2. model_settings.config is also read for foreign files (_load_model_from_file, branch BBS_MODEL_CONFIG_FILE; errors are fatal only for its own files). <object id> is matched via the ID of the build item object, <part id> via the ID of the sub-object (_handle_start_config_volume: without a triangle range, subobject_id counts; _generate_volumes_new looks for volume_iter.subobject_id == sub_object->id). All other keys of a part go into the volume configuration (volume->config.set_deserialize), including extruder.
  3. Components without p:path refer to objects of the same file (_handle_start_component: empty path = current model); _generate_current_object_list resolves them into sub-objects, each component becomes a sub-part (volume) of the same object with the component's transformation (none here).
  4. One volume: after loading, the importer removes the extruder of a single volume; then the object's applies – that is why we also write it on the object.
  5. Colors: the parser compares element names literally with m:colorgroup/m:color (prefix m required). With pid/pindex on the mesh object every triangle gets the color (_handle_start_triangle), and current Bambu Studio offers the color dialog on opening (Plater.cpp: extract_colors_to_obj_dialog, ObjColorDialog); "Append" adds the colors as filaments, and with colors per volume ObjColorPanel::apply_volume_filament_ids sets the extruders per volume without painting over the volume boundaries. Older versions and OrcaSlicer use the color group only at object level and without metadata.
  6. No project_settings.config: Bambu Studio loads it only from its own files (dont_load_config = true without generator version); OrcaSlicer always loads it and applies it over its defaults (config += config_loaded) – a file with only filament_colour would reset printer and process settings there. The filament colors therefore come from the color dialog (Bambu) or from the user/AMS sync.
  7. Missing filaments: on import (geometry only) Bambu Studio extends the filament list up to the highest extruder in the file (Plater.cpp: "add extruder … if only import geometry", with colors from get_next_color_for_filament).

10 Instructions: open in Bambu Studio

There was no Bambu Studio in the container; please verify these steps yourself. Described is what the source code leads one to expect.

  1. Export: in the UI "Colors & filaments" → 3MF multi-color (with parts, one object per part) or cad export modell.scad -o modell.3mf. The color list shows slot, volume and mass per color beforehand; slots are changed via the selector (writes filament = n).
  2. In Bambu Studio choose File → Import → 3MF/STL… (Ctrl+I) (or drag the file into the window, or "Open project"). The file does not come from Bambu Studio; expect the notice that only geometry (and colors) are loaded – that is correct.
  3. Color dialog (current versions): Bambu Studio shows the colors of the file (e.g. white, teal, red, blue, yellow) and suggests filaments for them. "Append" (German UI: „Anhängen“) creates the colors as new filaments; mapping to existing filaments puts the colors on the AMS slots; confirm. With colors per sub-part, each sub-part stays entirely in its filament.
  4. Without the color dialog (older version, OrcaSlicer or cancelled): the slots from the file apply. In the object list (left) the objects schild and figur appear; expanded, one sub-part per color ("schild – white", "schild – teal", "schild – red" …), next to it the filament number (1, 2, 3 …). Bambu Studio adds missing filaments on import up to the highest slot (with its own colors); then choose the right colors/AMS slots in the filament bar ("Sync AMS").
  5. Check: the sub-parts of an object sit exactly on each other (common origin), the lettering stands as relief on the plate, the collar sits at the neck of the figure. "Arrange objects" only moves whole objects.
  6. Slice: in the preview choose the view "Filament" – each color in its color, filament changes at the color boundaries, prime tower with several filaments. Compare the mass per filament with the color list (PLA 1.24 g/cm³; the slicer computes with walls/infill, hence different).

OrcaSlicer: as above without the color dialog – sub-parts and slots from model_settings.config, set the filament colors yourself. PrusaSlicer does not read this metadata: there use "STL per color (ZIP)", load all STLs together and answer Yes to "Multi-part object?", then set the extruder per sub-part (file names F<slot>_<farbe>.stl).

11 Known limitations

  • Color regions depend on SMLib's booleans: where SMLib loses material (e.g. union with a torus, known since report 1 – the example therefore uses a ring made from a cylinder), the regions are wrong; the engine warns ("sum ≠ volume") or reports an error. About three booleans per color node; the UI requests the regions only while the color list is open.
  • Bodies that meet only along a line do not give a closed body (found with the first letter "D": two bars touched only along an edge, lib3mf reported the mesh as non-manifold; now they overlap).
  • color() in 2D subtrees (below linear_extrude etc.) colors faces but does not split volume. Material outside the parts is missing from the color list if there are parts.
  • Filament colors in Bambu Studio via the color dialog or by hand (no project_settings.config, see 5.6); not checked in Bambu Studio and OrcaSlicer in the container. PrusaSlicer: components become separate objects, no slots.
  • Color per face in the view via the face tag: two bodies with identical content and different colors share one tag and both show the first color (known limitation of the provenance); "Show color regions" is not affected.
  • Color vision deficiency: see section 2 (smallest ΔE with deuteranopia 0.070, tritanopia 0.031). White on a light and black on a dark background distinguishable only by shading and edges.
  • Theme "System" in Tauri depends on the GTK color scheme; under Xvfb without a scheme it is light. Measurements and images under Xvfb/SwiftShader without GPU.
