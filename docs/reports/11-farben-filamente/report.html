1 Auftrag und Ergebnis

Drei Nutzerwünsche: Mehrfarbigkeit mit einem Export, den Bambu Studio „recht einfach mit mehreren Filamenten“ druckt; die CSS-Farben durch ein kleines, schönes Preset ersetzen (nur englische Namen, gedeckte Töne, Warnung und Zufallsfarbe bei unbekannten Namen); ein gründlich überarbeitetes dunkles Thema. Umgesetzt:

  • Palette mit 16 Farben in cad-eval (eine Quelle, für UI generiert), unbekannte Namen → Warnung „Farbe x unbekannt – Zufallsfarbe“ und stabile Farbe aus dem Hash des Namens; Hex, Vektoren und alpha exakt (Abschnitt 2).
  • Farbregionen: jedes Bauteil wird über Kernel-Booleans in Körper je Farbe geteilt (gecacht), Summe der Volumen = Bauteilvolumen; Filament-Slots aus color("teal", filament = 2) oder automatisch (Abschnitt 3).
  • 3MF für Bambu Studio / OrcaSlicer: ein Objekt je Bauteil, ein Teil je Farbe am selben Ursprung, Farbgruppe und Metadata/model_settings.config mit extruder je Teil – das Format aus dem Quellcode der Slicer erarbeitet (Abschnitt 5), geprüft mit lib3mf, trimesh, einem Modell des Bambu-Importers und PrusaSlicer (Abschnitt 6). Dazu „ein STL je Farbe“ als ZIP. CLI: cad export -o x.3mf ist mehrfarbig (--single-color), cad outline und cad measure --colors zeigen Farben, Slots, Volumen und Masse.
  • UI: „Farben & Filamente“ (Farbfeld, Name, Zeilen, Slot-Auswahl, die filament = n in den Code schreibt, Volumen und Masse bei PLA 1,24 g/cm³), Farbe je Fläche in der Ansicht, „Farbregionen zeigen“ (Abschnitt 7).
  • Dunkles Thema: Auswahl System (Standard, folgt prefers-color-scheme, auch in Tauri)/Hell/Dunkel, Token-Satz mit WCAG-Prüfung (Text ≥ 4,5:1), Editor-Teile mit eigenem Standardthema angepasst, Palette-Farben im Dunkeln leicht aufgehellt; cad render --theme dark (Abschnitt 8).

3 Regeln: Farbregionen und Filamente

Farbregionen (Volumen je Farbe)

  • Der Körper eines gefärbten Teilbaums gehört seiner Farbe: das Ergebnis des color()-Knotens, ins System des Bauteils gelegt (lokale Matrizen und resize-Faktoren auf dem Weg).
  • Überlappen sich Farben, gewinnt die spätere Anweisung, die frühere wird um sie verringert; „später“ heißt Pre-Order im Baum: ein inneres color() nach dem äußeren, ein späteres Geschwister nach dem früheren.
  • Abgezogenes gilt für alle: jedes Stück wird mit dem Ergebnis geschnitten (difference nimmt allen Farben das Loch); Farben, die nur in abgezogenen Operanden vorkommen, bekommen keinen Slot.
  • Material in keinem gefärbten Teilbaum (z. B. die Verrundung zwischen zwei Farben) gehört zur Farbe am Bauteil, sonst zum Standard-Eintrag (wenn das Bauteil ungefärbte Primitive hat), sonst zur ersten Farbe des Bauteils.
  • Rechnung: Stück(C) = R ∩ M(C) − ⋃ M(später), Rest R − ⋃ M, Stücke einer Farbe vereinigt, leere verworfen; je Farbknoten etwa drei Booleans. Ergebnis je Bauteil eine Liste (Farbe, Slot, Körper) mit Volumen; weicht die Summe vom Bauteilvolumen ab, warnt die Engine („Farbregionen ungenau“). Gecacht unter Bauteil, Farbknoten, Lagen und Farben; Farbe und Slot sind nicht Teil der Knotenschlüssel – eine neue Farbe oder ein neuer Slot rechnet keinen Knoten neu (Test regions_are_cached…). Ohne Farbknoten unter dem Bauteil gibt es keinen Boolean: eine Region aus den Körpern des Bauteils, Volumen = gecachtes Bauteilvolumen (Test uncoloured_part_needs_no_boolean).

Filament-Slots

  • color("teal", filament = 2) legt den Slot der Farbe fest (1–16, benanntes Argument; die erste Angabe gilt, ein Widerspruch warnt).
  • Material ohne color() („Standard“, #c3c8cf) druckt mit Slot 1.
  • Alle anderen Farben bekommen in Reihenfolge ihres ersten Auftretens den niedrigsten freien Slot. Gleiche Farbe in anderer Schreibweise ("gray", "GREY", "#7b7d81") ist derselbe Eintrag.
  • Slot in der UI ändern = Text-Edit (SetFilament): jede color()-Anweisung der Farbe mit filament = … bekommt den neuen Wert, sonst die erste , filament = n; „automatisch“ entfernt das Argument. Begründung: der Code bleibt die einzige Quelle (CLI-Export und UI-Export stimmen überein, der Agent sieht dasselbe), Undo und Git-Rand erfassen die Änderung; ein Vorschau-Override wie in der Parameterleiste ginge beim Speichern verloren und wäre für den Export eine zweite Wahrheit.

Quelltext
// Zweck: Mehrfarbig drucken (Bericht 11) – Türschild mit Schrift-Relief und Spielfigur als
// zwei Bauteile, Farben aus der Palette, ein fester Filament-Slot; Export als 3MF mit einem
// Teil je Farbe für Bambu Studio / OrcaSlicer.

// Blockbuchstaben aus Balken: s = Strichstärke, b × h = Feld des Buchstabens.
module balken(x, y, w, h, t) translate([x, y, 0]) cube([w, h, t]);

module buchstabe(c, b = 8, h = 12, s = 2, t = 1.2) {
    if (c == "C") {
        balken(0, 0, s, h, t);
        balken(0, h - s, b, s, t);
        balken(0, 0, b, s, t);
    } else if (c == "A") {
        balken(0, 0, s, h, t);
        balken(b - s, 0, s, h, t);
        balken(0, h - s, b, s, t);
        balken(0, h / 2 - s / 2, b, s, t);
    } else if (c == "D") {
        // Balken überlappen (nur Kanten berühren gäbe keinen geschlossenen Körper)
        balken(0, 0, s, h, t);
        balken(0, h - s, b - s / 2, s, t);
        balken(0, 0, b - s / 2, s, t);
        balken(b - s, s / 2, s, h - s, t);
    }
}

module schild(w = 60, d = 28, t = 3, rand = 2.5) {
    grid g {
        x: links = 0, schrift = 15, rechts = w;
        y: vorne = 0, zeile = 8, hinten = d;
        z: boden = 0, oben = t;
    }
    difference() {
        union() {
            // Grundplatte weiß, Rahmen petrol (sitzt auf der Platte)
            color("white") box(g[links, vorne, boden], g[rechts, hinten, oben]);
            color("teal") difference() {
                box(g[links, vorne, oben] - [0, 0, 0.5], g[rechts, hinten, oben] + [0, 0, 1]);
                box(g[links, vorne, oben] + [rand, rand, -1], g[rechts, hinten, oben] - [rand, rand, -2]);
            }
            // Schrift-Relief rot, auf Filament 3 festgelegt
            color("red", filament = 3)
                for (i = [0:2]) translate(g[schrift, zeile, oben] + [i * 11, 0, -0.2]) buchstabe(["C", "A", "D"][i]);
        }
        // Aufhängebohrung: abgezogen, gilt für alle Farben
        translate(g[links, hinten, boden] + [6, -6, -1]) cylinder(h = t + 3, r = 1.6);
    }
}

module spielfigur(r = 9, h = 26) {
    grid p {
        x: achse = 0, hals = r * 0.3, rand = r * 0.85, fuss = r;
        y: boden = 0, sockel = 4, mitte = h * 0.55, kopf = h * 0.8;
    }
    // Profil: vom Rand des Sockels zum Hals (quadratisch), dann gerade bis zum Kopf
    z0 = p.sockel - 1;
    profil = concat(
        [[0, z0]],
        [for (i = [0:16]) let (t = i / 16) [p.hals + (p.rand - p.hals) * (1 - t) * (1 - t), z0 + t * (p.mitte - z0)]],
        [[p.hals, p.kopf], [0, p.kopf]]);
    color("blue") {
        cylinder(h = p.sockel, r = p.fuss);
        rotate_extrude() polygon(profil);
    }
    // weißer Kragen und gelber Kopf: spätere Anweisungen gewinnen bei Überlappung
    color("white") translate([0, 0, p.mitte - 1]) cylinder(h = 2, r = r * 0.5);
    color("yellow") translate([0, 0, p.kopf + 2.5]) sphere(r * 0.42);
}

// Spielfigur neben dem Schild (eigenes Bauteil = eigenes Objekt im Slicer)
module figur(at = [80, 14, 0]) translate(at) spielfigur();

schild: schild();
figur: figur();

Annahmen und ihre Quellen

Gelesen im Quellcode von Bambu Studio (bambulab/BambuStudio, Zweig master) und OrcaSlicer (SoftFever/OrcaSlicer, Zweig main), abgerufen am 23.10.2026 über raw.githubusercontent.com (Prüfsummen unten):

  1. Fremde 3MF: Bambu Studio gilt eine Datei als eigene nur, wenn Application mit „BambuStudio-“ beginnt (_handle_end_metadata, OrcaSlicer zusätzlich „OrcaSlicer-“). Wir geben uns nicht als Bambu Studio aus; die Datei wird als „From_Other“ geladen (Model::read_from_archive; PrusaSlicer-Dateien erkennt PrusaFileParser am Namen „PrusaSlicer“).
  2. model_settings.config wird auch für fremde Dateien gelesen (_load_model_from_file, Zweig BBS_MODEL_CONFIG_FILE; Fehler nur für eigene Dateien fatal). <object id> wird über die ID des Build-Item-Objekts zugeordnet, <part id> über die ID des Unterobjekts (_handle_start_config_volume: ohne Dreiecksbereich zählt subobject_id; _generate_volumes_new sucht volume_iter.subobject_id == sub_object->id). Alle übrigen Schlüssel einer part landen in der Volumen-Konfiguration (volume->config.set_deserialize), also auch extruder.
  3. Komponenten ohne p:path verweisen auf Objekte derselben Datei (_handle_start_component: Pfad leer = aktuelles Modell); _generate_current_object_list löst sie in Unterobjekte auf, jede Komponente wird ein Teil (Volumen) desselben Objekts mit der Transformation der Komponente (hier keine).
  4. Ein Volumen: nach dem Laden entfernt der Importer das extruder eines einzigen Volumens; dann gilt das des Objekts – deshalb schreiben wir es auch am Objekt.
  5. Farben: der Parser vergleicht Elementnamen wörtlich mit m:colorgroup/m:color (Präfix m nötig). Mit pid/pindex am Netz-Objekt bekommt jedes Dreieck die Farbe (_handle_start_triangle), und das aktuelle Bambu Studio bietet beim Öffnen den Farbdialog an (Plater.cpp: extract_colors_to_obj_dialog, ObjColorDialog); „Append“ fügt die Farben als Filamente hinzu, und bei Farben je Volumen setzt ObjColorPanel::apply_volume_filament_ids die Extruder je Volumen, ohne die Volumengrenzen zu übermalen. Ältere Versionen und OrcaSlicer nutzen die Farbgruppe nur auf Objektebene und ohne Metadaten.
  6. Kein project_settings.config: Bambu Studio lädt es nur aus eigenen Dateien (dont_load_config = true ohne Generator-Version); OrcaSlicer lädt es immer und legt es über seine Standardwerte (config += config_loaded) – eine Datei nur mit filament_colour setzte dort Drucker- und Prozesseinstellungen zurück. Die Filamentfarben kommen deshalb aus dem Farbdialog (Bambu) oder vom Nutzer/AMS-Abgleich.
  7. Fehlende Filamente: beim Import (nur Geometrie) ergänzt Bambu Studio die Filamentliste bis zum höchsten extruder der Datei (Plater.cpp: „add extruder … if only import geometry“, mit Farben aus get_next_color_for_filament).

10 Anleitung: In Bambu Studio öffnen

Im Container gab es kein Bambu Studio; diese Schritte bitte selbst prüfen. Beschrieben ist, was nach dem Quellcode zu erwarten ist.

  1. Exportieren: in der UI „Farben & Filamente“ → 3MF mehrfarbig (bei Bauteilen ein Objekt je Bauteil) oder cad export modell.scad -o modell.3mf. Die Farbliste zeigt vorher Slot, Volumen und Masse je Farbe; Slots ändern sich über die Auswahl (schreibt filament = n).
  2. In Bambu Studio Datei → Importieren → 3MF/STL… (Strg+I) wählen (oder die Datei ins Fenster ziehen bzw. „Projekt öffnen“). Die Datei stammt nicht von Bambu Studio; erwartet ist der Hinweis, dass nur Geometrie (und Farben) geladen werden – das ist richtig so.
  3. Farbdialog (aktuelle Versionen): Bambu Studio zeigt die Farben der Datei (z. B. weiß, petrol, rot, blau, gelb) und schlägt Filamente dafür vor. Mit „Append“ / „Anhängen“ werden die Farben als neue Filamente angelegt, mit der Zuordnung zu vorhandenen Filamenten die Farben auf die Slots im AMS gelegt; bestätigen. Bei Farben je Teil bleibt jedes Teil ganz in seinem Filament.
  4. Ohne Farbdialog (ältere Version, OrcaSlicer oder abgebrochen): die Slots aus der Datei gelten. In der Objektliste (links) erscheinen die Objekte schild und figur; aufgeklappt je ein Teil pro Farbe („schild – white“, „schild – teal“, „schild – red“ …), daneben die Filamentnummer (1, 2, 3 …). Fehlende Filamente ergänzt Bambu Studio beim Import bis zum höchsten Slot (mit eigenen Farben); dann in der Filamentleiste die richtigen Farben/AMS-Slots wählen („AMS synchronisieren“).
  5. Prüfen: die Teile eines Objekts sitzen genau aufeinander (gemeinsamer Ursprung), die Schrift steht als Relief auf der Platte, der Kragen sitzt am Hals der Figur. „Objekte anordnen“ verschiebt nur ganze Objekte.
  6. Slicen: in der Vorschau die Ansicht „Filament“ wählen – jede Farbe in ihrer Farbe, Filamentwechsel an den Farbgrenzen, Prime Tower bei mehreren Filamenten. Masse je Filament mit der Farbliste vergleichen (PLA 1,24 g/cm³; der Slicer rechnet mit Wänden/Füllung, daher anders).

OrcaSlicer: wie oben ohne Farbdialog – Teile und Slots aus model_settings.config, Filamentfarben selbst setzen. PrusaSlicer liest diese Metadaten nicht: dort „STL je Farbe (ZIP)“ nehmen, alle STL zusammen laden und bei „Mehrteiliges Objekt?“ Ja wählen, dann je Teil den Extruder setzen (Dateinamen F<slot>_<farbe>.stl).

11 Bekannte Grenzen

  • Farbregionen hängen an den Booleans von SMLib: wo SMLib Material verliert (z. B. Vereinigung mit einem Torus, bekannt seit Bericht 1 – das Beispiel nutzt deshalb einen Ring aus einem Zylinder), stimmen die Regionen nicht, die Engine warnt („Summe ≠ Volumen“) oder meldet einen Fehler. Je Farbknoten etwa drei Booleans; die UI fragt die Regionen nur bei offener Farbliste an.
  • Kanten, die nur auf einer Linie zusammenstoßen, ergeben keinen geschlossenen Körper (beim ersten Buchstaben „D“ gefunden: zwei Balken berührten sich nur an einer Kante, lib3mf meldete das Netz als nicht mannigfaltig; jetzt überlappen sie).
  • color() in 2D-Teilbäumen (unter linear_extrude usw.) färbt Flächen, teilt aber kein Volumen. Material außerhalb der Bauteile fehlt in der Farbliste, wenn es Bauteile gibt.
  • Filamentfarben in Bambu Studio über den Farbdialog oder von Hand (kein project_settings.config, siehe 5.6); in Bambu Studio und OrcaSlicer nicht im Container geprüft. PrusaSlicer: Komponenten werden eigene Objekte, keine Slots.
  • Farbe je Fläche in der Ansicht über den Flächen-Tag: zwei inhaltsgleiche Körper mit verschiedenen Farben teilen sich einen Tag und zeigen beide die erste Farbe (bekannte Grenze der Provenienz); „Farbregionen zeigen“ ist davon nicht betroffen.
  • Farbfehlsichtigkeit: siehe Abschnitt 2 (kleinste ΔE bei Deuteranopie 0,070, Tritanopie 0,031). Weiß auf hellem und Schwarz auf dunklem Hintergrund nur über Schattierung und Kanten unterscheidbar.
  • Thema „System“ in Tauri hängt am GTK-Farbschema; unter Xvfb ohne Schema ist es hell. Messwerte und Bilder unter Xvfb/SwiftShader ohne GPU.
