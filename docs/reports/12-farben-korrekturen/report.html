2 Findings

F1 (high) – same geometry, different colors

Cause
The cache key of a node does not contain the color (intended: a new color recomputes nothing). color("red") cube(5) and translate(…) color("blue") cube(5) therefore have the same cube node content, the same face tag and – from the cache – the same kernel faces. The view (tagColors: tag → first node with color) and STEP (nodes_for_tag(tag).first()) took the first color for all faces of this tag. The 3MF was correct because the color regions place the instances individually.
Fix
Cache reuse stays; the color is assigned via instances and regions: (1) for models with colors the view shows the color regions (the bodies of the 3MF) as soon as they are computed (UI "Show color regions" (German UI: „Farbregionen zeigen“), now the default; cad render without --show faces); (2) the color per face (before that, for highlighted subtrees and --show faces) only takes nodes below the drawn node and, among several with the same content, the one whose bounding box contains the triangle (faceColors in web/src/logic/colors.ts, face_colors in cad-cli/src/render.rs); (3) STEP face colors come from the rule set of the regions without boolean: sample points of each face against the placed material of each color node (kernel.classify), the latest wins (Engine::face_region_colors), as synthetic tags in a copy of the B-rep.

F2 (high) – slot choice with a parameter or loop color

Cause
SetFilament wrote filament = n on the first color() statement of the color. With module bar(c) color(c) … or for (i) color(names[i]) … this statement colors several colors – all of them got the slot (or the first specification won with a warning).
Decision
A slot table in the code: filament("red", 4); at the top level of the main file, one statement per color. Reason: the code stays the only source (CLI and UI export the same, undo/Git see the change, an agent reads it too); the table applies to exactly one color and is independent of where the color arises (parameter, loop, library); it is an ordinary module call (no new syntax, OpenSCAD only reports an unknown module); a block filaments { … } would need parser changes, $filaments = […] would have the scoping rules of $ variables and could be overridden anywhere. The UI still writes filament = n on the statement if all statements of the color name it as a literal (readable in place), otherwise the table line; if there is a table line, it changes its slot, "automatic" removes the line.
Rules
The table is evaluated before all other statements (separate pass) and takes precedence; a contradicting filament = m warns and is ignored; filament() in modules, loops or libraries warns („nur auf oberster Ebene der Hauptdatei“, "only at the top level of the main file"); a user's own module filament takes precedence.

F3 (medium) – view ≠ print

Cause
(a) With overlap the kernel merges coplanar faces of both bodies into one face with one tag – the color per face cannot show the color boundary. (b) The fillet at a color boundary belongs to the uncolored union node (shown gray), the regions give it the remainder color (red). (c) color() in the 2D profile: the view showed the color of the 2D leaf, the color table did not look below profile operations (default, no entry, no warning).
Fix
(a, b) The view shows the color regions (F1). (c) If all 2D leaves of an extrusion without its own color have the same color, the extrusion is a body of that color (as with color() around it); mixed 2D colors are not separated: one body in the default color and the warning „Farben im 2D-Profil von linear_extrude werden nicht getrennt …“ ("colors in the 2D profile of linear_extrude are not separated …").

F5 (medium) – random colors collide

Cause
Only the hue came from the hash (L, C fixed): names fell onto the same value (baz/violet, x/rose) and were merged into one entry and slot; others lay close to palette colors.
Fix
Hue, lightness (0.45–0.80) and chroma (0.06–0.16) from the hash; one candidate sequence per name (SplitMix64); the first candidate with ΔEOK ≥ 0.07 to palette and default and – within the model, in order of first occurrence – ≥ 0.06 to the random colors of other names is chosen. Different names thus never coincide by chance; entries are merged only for exactly the same value (e.g. "#f00" and [1, 0, 0]).
Evidence
randnames.scad: 34 unknown names (36 statements, rot/Rot/ROT is one name), 34 entries on 34 different slots; smallest distance between two random colors ΔEOK 0.060 (gelb/violet), to the palette 0.071 (rot ↔ #c74240).

F7 – alpha, clamping, transparent, empty name

Rules
The identity of a print color is its RGB value: alpha only affects the view (the color region is drawn transparent), color("red", alpha = 0.5) is the entry red (one slot, the conflict check ignores alpha). Vector values and alpha outside 0–1 are clamped with a warning (for 0–255 values with a hint to "#rrggbb"). color("transparent") is not a print color: warning, the material stays default (no filament #00000000); color("") and color() warn and do not color.

Daemon – socket path longer than the Unix limit

Cause
sun_path holds 108 bytes (Linux; 107 without NUL). With a deep CAD_IPC_DIR, bind failed ("path must be shorter than SUN_LEN") and the client silently computed without the daemon.
Fix
cad_ipc::socket_path_in: if <dir>/<name>.sock is too long, the socket is placed in /tmp/cad-<uid>/<hash>-<name>.sock (directory with the same checks: 0700, own user, no symlink; hash = FNV-1a of the canonical runtime directory, so that several long directories do not interfere). Lock and log file stay in the runtime directory; list also finds substitute sockets (UI endpoints); cad daemon status shows the path with „Ersatzpfad“ ("substitute path", JSON socket_substitute), the log names it.

6 Limitations

  • The view shows the exact regions only after they are computed (booleans per color node, cached); until then, while dragging and for the highlighted subtree under the cursor, the approximated color per face applies. If the cursor is on a statement, the rest is shown dimmed (as before).
  • STEP does not split faces at color boundaries (a merged face gets the majority color).
  • Mixed colors in a 2D profile below an extrusion are not separated (warning).
  • Random colors that have to move away within the model depend on the names before them.
  • Bambu Studio and OrcaSlicer were not checked in the programs themselves, but via their source code and a model of the importer (tools/report/verify3mf.py).
  • The substitute socket is always under /tmp (not $TMPDIR, which can itself be long).
