1 Task and result

Step 1 of plan 17: sketches – a 2D block of segments (lines, circular arcs, Bézier curves, splines), each line of code one segment with its own display, its own handles and its own errors – as a profile for linear_extrude, rotate_extrude, loft and sweep (also as a path), exact through the kernel all the way to STEP; and modules as namespaces (teile.schraube(d = 3)). Draw mode (step 4) and corner/offset/stroke (step 2) are not part of this; corner() is reserved (warning).

  • Volumes against formulas (section 5): all cases within the integration accuracy of SMLib (≤ 3.9·10−6 relative; the twist extrusion is a cubic loft approximation as before).
  • STEP: arcs as CIRCLE, lines as LINE, extruded arcs as CYLINDRICAL_SURFACE, no approximated edges; OpenCASCADE reads all four new examples with the same volume (≤ 10−6).
  • OpenSCAD files unchanged: compare.py 33/33; user modules named line/arc and spline(points) outside sketches behave as before (tests).

2 Sketches: language

Decisions (plan 17.8): sketch is a built-in 2D module; sketch { and hole { work without parentheses; segments are ordinary statements that append to the sketch currently being evaluated – also from within modules and loops. Inside a sketch, segment names take precedence over user modules of the same name; outside, everything stays as in OpenSCAD. Other geometry and transformations inside a sketch are an error. Each sketch is one node Profile::Sketch; the segment statements are stored in EvalOutput::sketches so that the cache key does not depend on source positions.

SegmentForms
start(p)starts a contour; points may be grid points and anchors (z ≠ 0: warning, projected)
lineto = p, by = v (relative), length = l, angle = a; length alone continues the current direction
arcto, r [, large, cw] as in SVG · center, angle (degrees, sign = direction) · center, to · through, to · to alone = tangential
bezierc1, to (quadratic) · c1, c2, to (cubic)
splinepoints after the current point, tangent = true | v, end_tangent = v; cubic global interpolation (chord length, averaged knots)
close()line back to the start; if the contour ends at the start, it is closed even without close()
hole { … }contours inside are holes (in either direction)

Holes and multiple contours: winding rule nonzero; a contour is a boundary where the winding number is ≠ 0 on one side only; islands in holes via nesting. Sweep: without path, an open sketch (sketch(closed = false)) among the children is the path. Loft: equal segment count → segment by segment (each segment one face, matched via start); otherwise each section becomes a closed B-spline starting at the +x ray from the centroid (as for circles/polygons), so nothing twists.

// Purpose: sketches with arcs (plan 17.1) – a bracket as a sketch of lines and arcs with a
// grid inside the sketch, a bore (reverse direction, winding rule) and a slot
// (`hole { … }`), extruded; next to it a knob from a sketch with a tangential arc
// and a cubic Bézier curve, revolved about the z axis.
module halter(l = 60, b = 24, r_loch = 4) sketch {
    grid s {
        x: links = 0, bogen = l - b / 2;
        y: unten = 0, mitte = b / 2, oben = b;
    }
    start(s[links, unten]);
    line(to = s[bogen, unten]);
    arc(to = s[bogen, oben], r = b / 2);        // half circle at the end
    line(to = s[links, oben]);
    close();
    // bore around the arc center, clockwise: a hole (winding rule)
    start([l - b / 2 + r_loch, b / 2]);
    arc(to = [l - b / 2 - r_loch, b / 2], r = r_loch, cw = true);
    arc(to = [l - b / 2 + r_loch, b / 2], r = r_loch, cw = true);
    // slot: a hole in either direction
    hole {
        start([10, b / 2 - 3]);
        line(to = [26, b / 2 - 3]);
        arc(to = [26, b / 2 + 3], r = 3);
        line(to = [10, b / 2 + 3]);
        arc(to = [10, b / 2 - 3], r = 3);
    }
}

// Purpose: timing belt pulley (GT2-like) as a sketch via a loop (plan 17.1): each tooth gap
// is an arc through a point at the bottom of the gap, between them an arc around the center on
// the tip circle; the hub bore is a second contour, clockwise. Flanges as cylinders.
function polar(r, a) = [r * cos(a), r * sin(a)];

module scheibe(z = 20, teilung = 2, h = 7, bohrung = 5) {
    ra = z * teilung / PI / 2 - 0.25;           // tip circle radius
    t = 0.75;                                   // depth of the tooth gap
    dw = 0.6 / ra * 180 / PI;                   // half gap width as an angle
    a = 360 / z;
    translate([0, 0, 1]) linear_extrude(h) sketch {
        start(polar(ra, -dw));
        for (i = [0 : z - 1]) {
            arc(through = polar(ra - t, i * a), to = polar(ra, i * a + dw));
            arc(center = [0, 0], to = polar(ra, (i + 1) * a - dw));
        }
        start([bohrung / 2, 0]);
        arc(to = [-bohrung / 2, 0], r = bohrung / 2, cw = true);
        arc(to = [bohrung / 2, 0], r = bohrung / 2, cw = true);
    }
    for (zb = [0, h + 1]) translate([0, 0, zb]) difference() {
        cylinder(h = 1, r = ra + 1);
        translate([0, 0, -1]) cylinder(h = 3, d = bohrung);
    }
}

3 Modules as namespaces

module name { … } without parentheses; calls a.b.c(…), also named (k: teile.schraube();). The first part is looked up lexically, each further part only directly in the body of the previous module. The body is the namespace, with the parameters of the outer module at their default values; it belongs to no instance – the inner module does not see the grids, named instances and anchors of the outer one, and the geometry of the outer module is not created. Decision on functions/constants: reachable (teile.kopf(d), teile.M3) – libraries bundle helper functions and dimensions with their modules without a separate file; OpenSCAD has no dot after module names (no conflict); a variable of the same name shadows the module. Context: cad --module teile.platte.lochplatte, UI breadcrumb "teile › rohr" (S05).

// Purpose: modules as namespaces (plan 17.2) – a library `profile` with sketch modules
// and a parts library `teile` with constants, functions and submodules; calls from
// outside with a dot (`profile.stern()`, `teile.schraube(d = 3)`, multi-level
// `teile.platte.lochplatte()`), functions and constants as `teile.kopf(teile.M3)`.
module profile {
    module stern(n = 5, r1 = 12, r2 = 5) sketch {
        start([r1, 0]);
        for (i = [1 : n]) {
            line(to = [r2 * cos(360 * (i - 0.5) / n), r2 * sin(360 * (i - 0.5) / n)]);
            line(to = [r1 * cos(360 * i / n), r1 * sin(360 * i / n)]);
        }
    }
    module langloch(l = 20, b = 6) sketch {
        start([0, -b / 2]);
        line(to = [l, -b / 2]);
        arc(to = [l, b / 2], r = b / 2);
        line(to = [0, b / 2]);
        arc(to = [0, -b / 2], r = b / 2);
    }
}

module teile(raster = 10) {
    M3 = 3.2;                                   // M3 clearance hole
    function kopf(d) = 1.8 * d;                 // head diameter
    module schraube(d = 3, l = 12) {
        cylinder(h = l, d = d);
        translate([0, 0, l]) cylinder(h = d * 0.6, d = kopf(d));
    }
    module platte {
        // sees `raster` and `M3` of `teile` (default values)
        module lochplatte(n = 3) {
            difference() {
                cube([n * raster, raster, 3]);
                for (i = [0 : n - 1]) translate([raster * (i + 0.5), raster / 2, -1]) cylinder(h = 5, d = M3);
            }
        }
    }
}

4 Kernel integration

  • cad_kernel::Segment::{Line, Arc, Nurbs} (curve2.rs): NURBS form, affine mapping (arcs stay arcs under similarity transforms, otherwise exact rational elliptical arcs), sampling, global interpolation, joining into one B-spline (Bézier decomposition, degree elevation); Loop::Composite, PlacedPath, Kernel::sweep_path.
  • Facade smlib/facade/sc_sketch.cpp, included at the end of sc_facade.cpp (uses its internal helpers; compiled on its own it is empty). Loop kind 3: lines → SmLine, arcs → rational quadratic B-splines (SM_CF_CIRCULAR_ARC), Bézier/splines → B-splines; joints welded exactly. Changes to existing functions: one field in Loop, one branch each in parse_loops/loop_curves, the condition in the twist branch of sc_extrude, loft_segmentwise in sc_loft. New: sc_sketch_sweep (smooth path: curve sweep with profile reference point from patch 0003; corners: miter).
  • STEP: SMLib stores extruded arcs as SmSurfOfExtrusion of the exact B-spline; on such surfaces (without p-curves) OpenCASCADE computed volumes that were wrong by up to 2.5·10−3. The writer therefore writes an extrusion of a circular arc along its axis as CYLINDRICAL_SURFACE (orientation adjusted) – after that OCCT agrees to 10−9 or to the kernel accuracy, respectively.

7 UI: display and handles

When the cursor is in a sketch (segment line, loop, hole, call of a sketch module), the view draws it in its plane: mesh as an outline with a light fill (visible through the body), segments as lines, the segment of the cursor line thick in the accent color, errors red, control polygons and arc centers dashed, the start as a ring with a direction arrow, the end of open contours as a square. Handles: end/start points (literal or grid snap; line(by = …) relative, without snap), arc radius, center, through point, Bézier control points, spline points. Checks via the UI state (window.__cad) and pixels of the layers.

9 Limitations

  • corner, fillet2d, offset, stroke are missing (step 2); no transformations inside a sketch (a module called in a sketch draws in sketch coordinates).
  • Self-intersection is checked on sampled polylines (tolerance relative to the sketch size); intersections between contours are allowed (nonzero); the nesting of holes and islands assumes non-intersecting contours.
  • Sweep along a sketch with corners only as a miter and with the profile centered on the origin; closed paths are not supported.
  • Loft with different segment counts joins each section into one curve (C0 at the joints): the faces no longer follow the segments.
  • STEP: only extrusions of circular arcs are written as cylinders; surfaces of revolution of arcs remain SURFACE_OF_REVOLUTION of the exact curve (sphere/torus not recognized; OCCT reads them correctly).
  • cad render --line N of a segment line highlights the whole sketch; highlighting of the single segment exists only in the UI.
  • Namespaces: constants are evaluated in a new namespace on each access (no caching); --module name without a path takes the first module of that name.
