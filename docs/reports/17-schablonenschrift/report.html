1 Task and result

Plan 17.4 calls for a custom, very simple monospaced stencil font made of lines and arcs as the default font, with bridges so that no islands fall out. Implemented:

  • "cad stencil mono" (Regular, Bold) in crates/cad-font/src/stencil.rs: 125 glyphs – the whole required character set cad_font::REQUIRED_CHARS without fallback, plus ’ ” $. Each glyph is a sequence of center lines (lines, tangential circular arcs), drawn with a pen of the stroke width (flat ends, miter), plus dots, minus bridges, trimmed at the baseline and cap line. The contour is computed exactly by cad_kernel::region2 (pieces of the lines and arcs); STEP and the kernel see lines and circles.
  • No holes: every glyph, rendered to a profile, has 0 holes – the counters of O, A, B, D, P, R, 0, 4, 6, 8, 9, Ä, ö, @, %, &, §, °, Ø … are connected to the outside via bridges. Checked in cad-font for 8 combinations of stroke width and bridge width (regions without clockwise loops, closed loops, no slivers, no overlaps) and in the engine for every glyph via cad_engine::region_2d.
  • Parameters text(…, stroke_width = …, bridge_width = …) in mm: stroke width default 0.14·size (Bold 0.2·size), at most 0.2·size; bridge width default 0.1·size, 0 (no bridges – closed counters like a normal font) or 0.03…0.2·size. Values outside: warning at the argument, clamped. With other fonts: warning "wirkt nur mit …" ("only takes effect with …").
  • Metrics as for the other fonts: em = size/0.72, cap height = size (720/1000 em), advance 600/1000 em × 1000/1024 – exactly as JetBrains Mono, so texts stay as wide as with the previous default font.
  • Default font: text() without font and with an unknown family uses the stencil font (previously JetBrains Mono); missing characters (e.g. Cyrillic) still come from JetBrains Mono of the same weight.
  • Along the way: Playwright C16 (axis-constrained dragging, phase B), which recently failed even on its own, is fixed – the cause was in the test (handles of the previous cursor line, section 10).

2 Decisions

QuestionDecision
Form of the fontRust data instead of a font file: per character a small drawing function over named positions (center lines left/right/middle, baseline, x-height, cap height, ascender, descender, depending on the stroke width), building blocks stadium, bowl, C arc, dots, commas. No TTF build, no license question; Wasm growth is code only (section 8).
Strokeregion2::stroke (from step 2) with flat ends and miter: right angles stay square, ends are straight cuts (stencil look). Free ends run to the outer line (baseline, cap height), joints end on the center line of the other stroke – so no notches occur. Diagonals (A, K, M, N, V, W, X, Y, Z, 1, 2, 4, 7, /) are extended beyond the line and trimmed at the baseline/cap line (straight feet, flat apexes).
BridgesA bridge is a band of the bridge width across a stroke (length 1.3 half strokes to each side), subtracted from the glyph. Rules: stem separated from the bowl for B, D, P, R, b, d, g, p, q (bridges at the stem), round shapes at top and bottom (O, Q, 0, 8, o), open A (legs at the cap line apart by the bridge width), e and a at the crossbar or at the bowl next to the stem, 4 at the crossbar before the stem, 6/9 diagonally at the bowl, rings (°, %, Ø, @, &, §) on one side. ß/ẞ are open (gap ≥ bridge width to the stem).
Parametersstroke_width and bridge_width in mm (for printing and milling, absolute dimensions are what matters: "bridge at least two nozzle widths"); if not given, proportional to size. Style Bold = default stroke width 0.2·size. The limits come from the test of the parameter space: above 0.2·size strokes of a, e, #, @ grow together and close counters; bridges below 0.03·size are closed again by heavy strokes.
Metrics1000 units per em, cap height 720, x-height 530, ascender 760, descender −210, advance 600, side bearing 60 (glyph box 480 wide). Vertical text: advance 1000, glyph centered on the pen (as the shaper does for TrueType).
Default font and OpenSCADOpenSCAD does not know the font (without font it takes the fontconfig default font, usually Liberation Sans): a model without font looks different in OpenSCAD. The compatibility tests do not depend on it (section 9); anyone who needs the same dimensions as OpenSCAD specifies a bundled TrueType font. Unknown families → default font with a warning (previously JetBrains Mono).

6 Example: stencil

examples/spec/schablone.scad: text cut out of a 1 mm thin plate. Without bridges the inner parts of A, 0, 8, B, 9 would fall out; with the stencil font they stay attached to the plate.

// Purpose: spray stencil with the default font "cad stencil mono" (plan 17.4, report 17) – the
// text is cut out of a thin plate; the bridges of the font hold the inner parts
// of O, A, B, 0, 8 … on the plate, nothing falls out. Without `font` the stencil font applies;
// `stroke_width` (stroke width) and `bridge_width` (bridge width) in mm, `bridge_width = 0` without bridges.

breite = 120;
hoehe = 44;
dicke = 1;
r = 4;              // corner radius
groesse = 12;       // cap height
strich = 1.7;       // stroke width (default 0.14 · size)
steg = 1.2;         // bridge width (printing: at least two nozzle widths)

difference() {
    linear_extrude(dicke) offset(r = r) offset(delta = -r) square([breite, hoehe]);
    translate([breite / 2, 27, -1]) linear_extrude(dicke + 2)
        text("LACK 08", size = groesse, halign = "center", stroke_width = strich, bridge_width = steg);
    translate([breite / 2, 8, -1]) linear_extrude(dicke + 2)
        text("RAL 9005 B", size = 8, halign = "center", bridge_width = steg);
}

Printed: G-code from PrusaSlicer

A real print is not possible in this environment; instead: STL exported (cad export), sliced to G-code with PrusaSlicer 2.7 (default profile, layer 0.2 mm, nozzle 0.4 mm), and the top layer drawn from the G-code (tools/report/report17-gcode.py): every island of the plate is connected to the rest, the bridges (1.2 mm = 3 nozzle widths) are printed as separate paths.

7 How a glyph is built

Example B: stem vline(l, 0, cap); upper and lower bowl as a path from the stem (bowl: crossbar, quarter arcs, crossbar back); three bridges directly to the right of the stem (crossbars top, middle, bottom). region2::stroke turns the paths into bands, miter pieces and ends, region2::combine unites them and subtracts the bridges. Result: stem and "3"-shaped bowl as two closed contours of lines and arcs, without a hole. The positions depend on the stroke width (center line = outer line ∓ half stroke), so cap height and glyph box stay the same for every stroke width.

'B' => {
    g.vline(l, y0, cap);
    bowl(g, l, r - 0.06 * wd, t, m, (t - m) / 2.0);
    bowl(g, l, r, m, b, (m - b) / 2.0);
    for y in [t, m, b] {
        g.cut(l + h + bw / 2.0, y, 90.0);
    }
}

C16 axis-constrained dragging (report 4) – cause and fix

Since report 15, C16 ran into the test timeout depending on timing, recently also on its own. Cause: after clickLine(2, 3) the viewer rebuilds the handles only in the next animation frame; until then __cad.handles() returns the handles of the previous cursor line. That line holds cube([60, 30, 1]), whose vector is also a point handle – waitHandles("… kind === 'point'") was satisfied immediately, the test took the first handle (the plate corner at x = 1118 px instead of the translate point at 770 px), the drag did not start (drag() = null), the mouse rotated the camera, and waiting for "Achse x" ("axis x") ran until the timeout. The axis selection itself was correct in all runs. Fix in the test: pointHandleOn(page, zeile) waits for the point handle of the line and takes exactly that one (likewise C20, same gap). No test skipped.

12 Limitations

  • Design deliberately simple: one stroke width per glyph (only @ with 0.72 times the stroke, ² ³ with 0.75 times), no optical corrections, no kerning pairs (monospaced). W, w, m, @, * become very dense in Bold.
  • Parameter limits from the test (stroke ≤ 0.2·size, bridge 0 or 0.03…0.2·size); values in between checked at 8 combinations, not exhaustively. On arcs, a bridge is cut radially straight; its width applies on the center line.
  • The font does not compose combining characters (e.g. "a" + U+0308): the character comes from JetBrains Mono. Precomposed umlauts are included.
  • Characters outside the scope (Cyrillic, Greek, arrows …) come from JetBrains Mono – without bridges, so they can have holes.
  • Glyphs of different characters touch only with spacing < 1 or with the continuous strokes —, _ (across the whole cell as in monospace fonts); then counters can form between glyphs.
  • Models without font look different in OpenSCAD (fontconfig default there).
