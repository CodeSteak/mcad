1 Auftrag und Ergebnis

Plan 17.4 sieht als Standardschrift eine eigene, sehr einfache monospaced Schablonenschrift aus Geraden und Bögen vor, mit Stegen, sodass keine Inseln herausfallen. Umgesetzt:

  • „cad stencil mono“ (Regular, Bold) in crates/cad-font/src/stencil.rs: 125 Glyphen – der ganze Pflicht-Zeichensatz cad_font::REQUIRED_CHARS ohne Rückfall, dazu ’ ” $. Jede Glyphe ist eine Folge von Mittellinien (Geraden, tangentiale Kreisbögen), gezeichnet mit einem Stift der Strichstärke (flache Enden, Gehrung), plus Punkte, minus Stege, an Grund- bzw. Versallinie beschnitten. Die Kontur rechnet cad_kernel::region2 exakt aus (Stücke der Geraden und Bögen); STEP und Kernel sehen Geraden und Kreise.
  • Keine Löcher: jede Glyphe, zum Profil gerendert, hat 0 Löcher – Innenräume von O, A, B, D, P, R, 0, 4, 6, 8, 9, Ä, ö, @, %, &, §, °, Ø … sind über Stege mit dem Außenbereich verbunden. Geprüft in cad-font für 8 Kombinationen von Strichstärke und Stegbreite (Regionen ohne Uhrzeigersinn-Schleifen, geschlossene Schleifen, keine Splitter, keine Überlappungen) und in der Engine für jede Glyphe über cad_engine::region_2d.
  • Parameter text(…, stroke_width = …, bridge_width = …) in mm: Strichstärke Standard 0,14·size (Bold 0,2·size), höchstens 0,2·size; Stegbreite Standard 0,1·size, 0 (keine Stege – geschlossene Innenräume wie eine normale Schrift) oder 0,03…0,2·size. Werte außerhalb: Warnung am Argument, begrenzt. Bei anderen Schriften: Warnung „wirkt nur mit …“.
  • Metrik wie die übrigen Schriften: em = size/0,72, Versalhöhe = size (720/1000 em), Vorschub 600/1000 em × 1000/1024 – genau wie JetBrains Mono, sodass Texte gleich breit bleiben wie mit der bisherigen Standardschrift.
  • Standardschrift: text() ohne font und mit unbekannter Familie nutzt die Schablonenschrift (vorher JetBrains Mono); fehlende Zeichen (z. B. Kyrillisch) kommen weiter aus JetBrains Mono gleichen Gewichts.
  • Nebenbei: Playwright C16 (achsgebundenes Ziehen, Phase B), das zuletzt auch einzeln scheiterte, ist behoben – die Ursache lag im Test (Griffe der vorigen Cursorzeile, Abschnitt 10).

2 Entscheidungen

FrageEntscheidung
Form der SchriftRust-Daten statt Schriftdatei: je Zeichen eine kleine Zeichenfunktion über benannten Lagen (Mittellinien links/rechts/Mitte, Grund-, x-, Versal-, Ober-, Unterlänge, abhängig von der Strichstärke), Bausteine Stadion, Bauch, C-Bogen, Punkte, Kommas. Kein TTF-Build, keine Lizenzfrage; Wasm-Zuwachs nur Code (Abschnitt 8).
Strichregion2::stroke (aus Schritt 2) mit flachen Enden und Gehrung: rechte Winkel bleiben eckig, Enden sind gerade Schnitte (Schablonen-Anmutung). Freie Enden laufen bis zur äußeren Linie (Grundlinie, Versalhöhe), Stöße enden auf der Mittellinie des anderen Strichs – so entstehen keine Kerben. Diagonalen (A, K, M, N, V, W, X, Y, Z, 1, 2, 4, 7, /) werden über die Linie verlängert und an Grund-/Versallinie beschnitten (gerade Füße, flache Spitzen).
StegeEin Steg ist ein Band der Stegbreite quer über einen Strich (Länge 1,3 halbe Striche zu jeder Seite), von der Glyphe abgezogen. Regeln: Stamm getrennt vom Bauch bei B, D, P, R, b, d, g, p, q (Stege am Stamm), runde Formen oben und unten (O, Q, 0, 8, o), offenes A (Beine an der Versallinie um die Stegbreite auseinander), e und a am Querstrich bzw. am Bauch neben dem Stamm, 4 am Querstrich vor dem Stamm, 6/9 schräg am Bauch, Ringe (°, %, Ø, @, &, §) an einer Seite. ß/ẞ sind offen (Lücke ≥ Stegbreite zum Stamm).
Parameterstroke_width und bridge_width in mm (für Druck und Fräsen sind absolute Maße gefragt: „Steg mindestens zwei Düsenbreiten“); ohne Angabe proportional zu size. Stil Bold = Standard-Strichstärke 0,2·size. Die Grenzen kommen aus dem Test der Parameterfläche: oberhalb 0,2·size wachsen Striche von a, e, #, @ zusammen und schließen Innenräume; Stege unter 0,03·size schließen schwere Striche wieder.
Metrik1000 Einheiten je em, Versalhöhe 720, x-Höhe 530, Oberlänge 760, Unterlänge −210, Vorschub 600, Seitenrand 60 (Glyphenbox 480 breit). Senkrechter Text: Vorschub 1000, Glyphe mittig auf dem Stift (wie der Shaper bei TrueType).
Standardschrift und OpenSCADOpenSCAD kennt die Schrift nicht (es nimmt ohne font die fontconfig-Standardschrift, meist Liberation Sans): ein Modell ohne font sieht in OpenSCAD anders aus. Die Kompatibilitätstests hängen davon nicht ab (Abschnitt 9); wer gleiche Maße wie OpenSCAD braucht, gibt eine mitgelieferte TrueType-Schrift an. Unbekannte Familien → Standardschrift mit Warnung (vorher JetBrains Mono).

Alle 125 Glyphen direkt aus der Schrift (Beispielprogramm cargo run -p cad-font --example stencil_chart): Zelle = Vorschub, Linien Grundlinie, x-Höhe, Versalhöhe, Unterlänge. Eine Glyphe mit Loch wäre rot.

6 Beispiel: Schablone

examples/spec/schablone.scad: Text aus einer 1 mm dünnen Platte geschnitten. Ohne Stege fielen die Innenteile von A, 0, 8, B, 9 heraus; mit der Schablonenschrift hängen sie an der Platte.

// Zweck: Sprühschablone mit der Standardschrift „cad stencil mono“ (Plan 17.4, Bericht 17) – der
// Text ist aus einer dünnen Platte ausgeschnitten; die Stege der Schrift halten die Innenteile
// von O, A, B, 0, 8 … an der Platte, nichts fällt heraus. Ohne `font` gilt die Schablonenschrift;
// `stroke_width` (Strichstärke) und `bridge_width` (Stegbreite) in mm, `bridge_width = 0` ohne Stege.

breite = 120;
hoehe = 44;
dicke = 1;
r = 4;              // Eckenradius
groesse = 12;       // Versalhöhe
strich = 1.7;       // Strichstärke (Standard 0,14 · size)
steg = 1.2;         // Stegbreite (Druck: mindestens zwei Düsenbreiten)

difference() {
    linear_extrude(dicke) offset(r = r) offset(delta = -r) square([breite, hoehe]);
    translate([breite / 2, 27, -1]) linear_extrude(dicke + 2)
        text("LACK 08", size = groesse, halign = "center", stroke_width = strich, bridge_width = steg);
    translate([breite / 2, 8, -1]) linear_extrude(dicke + 2)
        text("RAL 9005 B", size = 8, halign = "center", bridge_width = steg);
}

Gedruckt: G-Code aus PrusaSlicer

Ein echter Druck ist in dieser Umgebung nicht möglich; stattdessen: STL exportiert (cad export), mit PrusaSlicer 2.7 (Standardprofil, Schicht 0,2 mm, Düse 0,4 mm) zu G-Code geschnitten und die oberste Schicht aus dem G-Code gezeichnet (tools/report/report17-gcode.py): jede Insel der Platte ist mit dem Rest verbunden, die Stege (1,2 mm = 3 Düsenbreiten) werden als eigene Bahnen gedruckt.

7 Wie eine Glyphe entsteht

Beispiel B: Stamm vline(l, 0, cap); oberer und unterer Bauch als Pfad vom Stamm (bowl: Querstrich, Viertelbögen, Querstrich zurück); drei Stege direkt rechts neben dem Stamm (Querstriche oben, Mitte, unten). region2::stroke macht aus den Pfaden Bänder, Gehrungsstücke und Enden, region2::combine vereinigt sie und zieht die Stege ab. Ergebnis: Stamm und „3“-förmiger Bauch als zwei geschlossene Konturen aus Geraden und Bögen, ohne Loch. Die Lagen hängen von der Strichstärke ab (Mittellinie = äußere Linie ∓ halber Strich), daher bleiben Versalhöhe und Glyphenbox bei jeder Strichstärke gleich.

'B' => {
    g.vline(l, y0, cap);
    bowl(g, l, r - 0.06 * wd, t, m, (t - m) / 2.0);
    bowl(g, l, r, m, b, (m - b) / 2.0);
    for y in [t, m, b] {
        g.cut(l + h + bw / 2.0, y, 90.0);
    }
}

12 Grenzen

  • Gestaltung bewusst einfach: eine Strichstärke je Glyphe (nur @ mit 0,72-fachem Strich, ² ³ mit 0,75-fachem), keine optischen Korrekturen, keine Kerning-Paare (monospaced). W, w, m, @, * werden bei Bold sehr dicht.
  • Grenzen der Parameter aus dem Test (Strich ≤ 0,2·size, Steg 0 oder 0,03…0,2·size); dazwischen geprüft an 8 Kombinationen, nicht lückenlos. Ein Steg ist an Bögen radial gerade geschnitten, seine Breite gilt auf der Mittellinie.
  • Kombinierende Zeichen (z. B. „a“ + U+0308) setzt die Schrift nicht zusammen: das Zeichen kommt aus JetBrains Mono. Vorkomponierte Umlaute sind enthalten.
  • Zeichen außerhalb des Umfangs (Kyrillisch, Griechisch, Pfeile …) kommen aus JetBrains Mono – ohne Stege, können also Löcher haben.
  • Glyphen verschiedener Zeichen berühren sich nur bei spacing < 1 oder den durchgehenden Strichen —, _ (über die ganze Zelle wie in Monospace-Schriften); dann können zwischen Glyphen Innenräume entstehen.
  • Modelle ohne font sehen in OpenSCAD anders aus (dort fontconfig-Standard).
