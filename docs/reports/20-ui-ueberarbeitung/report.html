1. What changed

  • Building blocks in web/src/app/ui/: Button (primary, standard, quiet, toggle with aria-pressed), IconButton, Segmented (radio group with arrow keys), MenuButton/SplitButton/ContextMenu (WAI-ARIA menus with submenus, rendered into <body>, never clipped), Toolbar/ToolGroup/ToolSep. One height 26 px, radius 6 px, Inter 12 px (the Inter 4.1 file shipped with cad-font – same widths in Chromium and WebKitGTK). Icons from Lucide (lucide-react 1.52, ISC), three custom ones in the same stroke (line, arc, ⊥). Tooltips with keyboard shortcut, aria-label = plain name, aria-keyshortcuts.
  • Header bar: app name, "File ▾" (German UI: „Datei ▾“; New, Open, Open folder, Recently opened ›, Save as, Add file, Load file, Load/save ZIP), "Examples ▾" with submenus, file name centered (change dot in the desktop app, path into the module context as previously in the path bar), "Save" primary, split export button (remembers the format, Ctrl+E), theme and settings icon buttons.
  • Editor: only tabs and "+"; right click/Shift+F10 on a tab: "Set as main file", "Close".
  • View: the rows "File …" and "Parts …" are gone. Toolbar at the top: on the left mode Model/Section/Sketch/Measure (exactly one), on the right Fit, View ▾ (Iso, Top, Front, Right, Back, Left, Bottom), All grids, Display ▾ (grid, color regions, side panel). The mode's context bar always at the top left below it. Clickable view cube at the bottom right instead of the axis triad.
  • Context bars: Section (X/Y/Z/View, position, flip, copy CLI), Sketch (icon groups, Arc ▾, keyboard shortcuts, "Done" primary), Measure (measurement kind as segmented control, "In section", copy, delete, "Done").
  • Side panel on the right, collapsible, tabs Parts (visibility, volume, export in the ⋯ menu, "without part", total), Colors, Measure, in the module context Parameters.
  • Accent teal: light #0f766e, dark #3cc4a8; likewise focus ring, selection/hover of the view (--view-accent, --view-flat, --hover-line, --viewhover-line); the model palette is unchanged.
  • Arch package/Wayland: the desktop file is named after the app ID (dev.controller-cad.desktop.desktop), the app sets the app ID as GLib program name (Wayland app_id, X11 WM_CLASS).

9. Arch package: app ID under Wayland

Under Wayland the taskbar maps a window to the desktop file of the same name via its app_id (KDE, GNOME). Tauri does not set the app ID itself (enableGTKAppId is off because a registered GApplication would hand a second instance over to the first); GTK therefore took the program name cad, and the desktop file was named controller-cad.desktop. Now:

  • crates/cad-app sets the GLib program name to the identifier from tauri.conf.json (dev.controller-cad.desktop) before GTK starts; GTK uses it as Wayland app_id and as X11 WM_CLASS. Configuration and WebView data stay under the same identifier (no migration).
  • The desktop file is named after the app ID: packaging/linux/dev.controller-cad.desktop.desktop, StartupWMClass=dev.controller-cad.desktop; make install derives the name from tauri.conf.json, make uninstall also removes the old name; packaging/arch/smoke-test.sh checks the file and WM_CLASS.

11. Deviations from the concept and limitations

  • Renaming a tab does not exist (did not exist before); the context menu has "Set as main file" and "Close".
  • Parameter bar: the concept does not mention it; it is now the "Parameters" tab of the side panel, which appears and is selected in the module context (before a separate column that narrowed the view further). On leaving the module the panel returns to the previous tab.
  • Path bar: the path into the module context sits centered in the header bar next to the file name (click jumps back), instead of in the removed row "File …".
  • X-ray/ghost in the view area: the UI had no such toggle (only the CLI cad render --xray); the other display options are in the "Display" menu (eye icon): All grids, Show color regions (also in the Colors tab), Side panel.
  • Measure additionally has "Done" (like Sketch); copy/delete act on the selected measurement, otherwise the last one. "In section" turns the section on; after "Done" the view is in Section mode (the section is view state, Measure and Sketch leave it in place).
  • Default split editor : view 33 : 67 (before 46 : 54; in the concept draft 30 %), so that toolbar and context bars stay single-line at 1280 px with the side panel open and the mode appears with text; the divider can still be dragged, narrow views show mode and measurement kind as icons.
  • Ctrl+N is intercepted only by the desktop app (Chromium reserves the key for a new window); in the browser no shortcut is shown on the menu item.
  • View cube: face centers are buttons with names ("View Top"), edges and corners mouse only; via keyboard there is the "View ▾" menu. The cube is an orthographic SVG projection (no perspective), a click jumps without animation.
  • The colors of the model palette, the git markers and syntax highlighting are unchanged; --view-profile (profiles, petrol) is close in color to the new accent.
  • Wayland itself cannot be checked in the container; what is checked is the program name (X11 WM_CLASS under Xvfb), which GTK also uses as app_id.
