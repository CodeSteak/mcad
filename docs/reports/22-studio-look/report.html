CLI: software renderer (crates/cad-render/src/studio.rs)

  • Deferred shading. With --style studio the rasteriser writes albedo and the interpolated (camera-facing) normal per supersample into a G-buffer instead of a shaded colour; section caps go in with their hatched colour. After the caps one parallel pass (rows over all cores, std::thread::scope) lights every opaque sample; edges, transparent bodies, overlays, labels and the axis triad are drawn afterwards as before.
  • Lights. Key light (Lambert + Blinn-Phong highlight, exponent 48) whose azimuth is relative to the camera like a turntable and whose elevation is measured from the xy plane, a weak fill light from the camera (+15°), hemisphere ambient light (white sky from +z, bounce tinted by the ground colour). A soft shoulder above 0.8 keeps directly lit light faces from burning out.
  • Shadows. Orthographic shadow map (2048², span-based rasteriser) of all opaque, clipped triangles along the key light; percentage-closer soft shadows: blocker search (12 Vogel samples) → penumbra from the blocker–receiver distance × tan(light radius) → 16 filter samples, rotated per sample by interleaved gradient noise, compared against the receiver plane (depth gradient from the normal) instead of one depth, plus normal offset. Tiles of 16×16 texels with their minimum depth skip the search where nothing can cast. Model on itself and on the ground; caps and transparent bodies cast none.
  • Ambient occlusion. Screen space from the linear depth buffer (including the ground): 16 hemisphere samples of radius --ao-radius (default 5 % of the model diagonal) around the normal, rotated in a 4×4 pattern, range check, then a depth- and normal-aware 4×4 blur. AO darkens the ambient light fully and the direct light by 55 %.
  • Ground and background. Plane z = lowest point of the model, drawn only where the camera looks down onto it (none in front/right/bottom views), not in the depth buffer of the overlays (grids and labels stay visible), faded into the background between 0.55 and 1.5 model diagonals. Background solid or vertical gradient (--background, also usable with standard). Edges at 35 % opacity.
  • Interfaces. RenderOptions::studio: Option<Studio>, background_bottom, CameraInfo::studio (light vector, ground height, AO radius, shadow map size); CLI options in ViewArgs (also mcad watch --render; the daemon forwards the arguments), JSON style, studio, background, views[].studio. Studio options without --style studio, out-of-range values and unknown colours exit with 2.

UI: three.js (web/src/view/viewer.ts, web/src/app/studio.tsx, web/src/logic/studio.ts)

  • Toggle “Studio look” and a settings panel in the view toolbar; settings in the store, kept in localStorage cad-studio (sanitised on load), same defaults as the CLI (Vitest checks both and the generated CLI arguments).
  • Directional key light with a 2048² variance shadow map (blur radius from the softness, as the CLI's penumbra at a typical distance), fill light and hemisphere light placed every frame from the camera azimuth (lightDirection, same convention as the Rust code); opaque meshes cast and receive shadows; materials a little glossier (roughness 0.5) and edges at 35 % opacity.
  • Ground: a transparent MeshStandardMaterial plane with a radial fade (shader chunk), receiving shadows; the floor grid is hidden while it is on. Background: a procedural 1×256 canvas gradient as scene.background (no image files).
  • Ambient occlusion: three.js GTAOPass (no new dependency) on the opaque model and the ground only; frame = model pass to the screen, AO multiplied on top, then the overlays (handles, grids, measurements, sketches, asserts) drawn over the kept depth buffer, so they are not darkened. Paused while a section is shown.
  • “Copy as mcad render” gives the CLI call of the current view (perspective, azimuth, elevation, theme) with the changed settings; mcad ui status reports studio with that call.

4 UI screenshots

Browser build with the Wasm kernel in Chromium (software WebGL via SwiftShader), window 1440×900; German UI as in all Playwright specs (“Studio-Darstellung” = studio look, “Studio-Einstellungen” = studio settings, “Umgebungsverdeckung” = ambient occlusion, “Schatten” = shadows, “Boden” = ground, “Hintergrund” = background, “Standardwerte” = defaults). The desktop app uses the same web UI.

S01 Studio look on and off

The button “Studio-Darstellung” (studio look) in the view toolbar switches to key/fill/sky light, soft shadows on the model and the ground, ambient occlusion and a fading ground on a gradient background; 50 % of the view pixels change. Frame time (software WebGL): standard 55.8 ms, studio 1932.7 ms, studio without AO 1395.3 ms.

S02 Settings panel and persistence

Panel “Studio-Einstellungen”: switching off ambient occlusion changes 1.2 % of the pixels, switching off shadows another 3.4 %; light direction 60°/25° is used (light vector z = sin 25°); after a reload the settings are still there (localStorage cad-studio); “Standardwerte” restores the defaults.

S03 Variants

Mug: default settings; light from the right at 30° with soft shadows (0.9); ground off on a white–blue gradient; dark theme (ground and gradient from the theme).

S04 Section and further models

Macropad (colours per part, keep-out volumes) in the studio look; the box with a section (caps, shadows; ambient occlusion pauses during a section, the panel says so); hook.

S05 Same look in the CLI

“Als mcad render kopieren” gives mcad render housing.mcad -o studio.png --perspective --azimuth 38.7 --elevation 29.3 --style studio --light -30,50 --shadow-softness 0.5; the call run with the CLI (size of the view, --no-axes) renders the same view in the CLI's software renderer.

S06 English UI

Browser language English: “Studio look” and “Studio settings” in the view toolbar, the panel with Light (Direction, Height, Intensity, Ambient), Shadows (Softness), Ambient occlusion (Radius, Strength), Ground (colour, Theme), Background (top, bottom, Theme), Defaults and “Copy as mcad render”.

The studio pass adds a roughly constant 0.9–1.1 s at 1024×768 (shadow map and lookups ≈ 0.4 s, AO ≈ 0.4 s, deferred lighting ≈ 0.15 s), so it weighs most on light models and scales with the pixel count (1920×1440: see the last row); the standard style is as fast as before the change (column “before”: the build of the commit before the change).

UI (Playwright S01, Chromium, SwiftShader (software WebGL), 1440x900 window, mean of 8 synchronous frames incl. readPixels): standard 55.8 ms, studio 1,932.7 ms, studio without AO 1,395.3 ms per frame. Software WebGL is far slower than a GPU; the numbers only compare the modes.

7 Known limitations

ItemCause or status
Screen-space AOOnly what is on screen occludes (in CLI and UI); very large radii darken silhouettes against far geometry less correctly. The UI's GTAO shows slight noise on software WebGL; the CLI is noise-free after supersampling and blur.
AO in the UI with a sectionpaused while a section is shown: the cut faces are stencil caps that the AO normal pass cannot reproduce (the panel says so). The CLI computes AO with sections.
Soft shadows differ in detailCLI: percentage-closer soft shadows (penumbra grows with the distance to the occluder). UI: variance shadow map with a constant blur radius derived from the same softness; contact hardening only in the CLI.
Shadow casterstransparent bodies (x-ray, dimmed rest, alpha) and section caps cast no shadow; the shadow map covers the model, very long shadows at low light elevation end where the ground fades.
Groundonly below the model and only when the camera looks down onto it; not in front/right/bottom views. A model “floating” above other parts is lit as one scene (no per-part ground).
Light follows the camera azimuthdeliberately (turntable): every view is lit from the front-left; in the UI the shadow turns while orbiting.
Run timestudio is 3.6× slower than standard in the CLI (table above); --shadows off --ao off keeps only the lighting.
Desktop appnot built or run here (no WebKitGTK); it embeds the same web UI.
